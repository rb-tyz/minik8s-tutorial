原教程范围对齐：实现与验收

本轮按 docs/TUTORIAL-ALIGNMENT-PLAN.md 修改参考实现。保留已审计的架构选择， 范围含原文 §14.4 的静态路由跨节点实验；DNS、NodePort、Ingress、CSI/PV/PVC、HPA、HA 继续按原文与项目约定分开安排。当前交付按实验正确性与教程覆盖验收。

本轮改动

  • 补上原文 §4 的 kubectl-mini JSON 客户端，支持 get/create/replace/patch/delete。
  • 普通对象增加 RFC 7396 对象形式的 Merge PATCH：显式 RV、递归对象合并、数组替换、 null 删除、原有身份/校验/CAS 保护；提供 Go Client.Patch 和公开黑盒检查。
  • scheduler 按原文的 CPU/memory 已用比例评分，同分按节点名排序，并处理整数乘法溢出。
  • Runtime 增加 CPU period/quota、cgroup v2 pids.max=512、RuntimeDefault seccomp 与 原文演示的能力集合。实际配置和值的检查见 VM 结果。
  • proxy 增加 --observer-only。每节点一个 proxy，全群只有指定进程分配 VIP，其他节点 消费 API 中的已发布地址并生成本地规则。
  • 双节点 runner 使用已有 QEMU user/socket 链路；guest 内各自配置不同 PodCIDR 和 对端静态路由。保留完整单节点验收，再执行双节点集成。
  • 真实镜像拉取实验使用只读 OCI 仓库 fixture 和带唯一层文件的新镜像，检查缺失、失败后 恢复与缓存命中。测试设施与产品代码分别存放。

保留的简化与提供的设施

API Server 内嵌 KV、HTTP NDJSON、containerd/crictl/runc 适配、串行周期协调的 kubelet、 单 scheduler/控制器、实时 List 建账与可选索引保持原有选择。它们的机制映射见对齐计划。 VM 身份校验、下载/部署脚本、测试镜像和仓库均是提供的实验设施，学习者可复用。

hostPath 指各节点自己的本地路径，不提供跨节点共享存储。Ready 按应用进程运行状态判断， 此轮沿用原文的基础控制流程，未新增探针体系、驱逐或节点硬故障迁移。

复现

下载并校验输入的方法见 VM 环境说明。在仓库根目录：

python3 reference/tests/vm/run.py \
  --image /path/to/base.qcow2 --sha512 <image_SHA512> \
  --crictl /path/to/crictl.tar.gz --crictl-sha256 <crictl_SHA256> \
  --two-node --output /tmp/opencode/original-scope-new-output

宿主机需要可用 KVM 和 QEMU 工具。guest 安装依赖时可指定 --apt-proxy；网络配置、CRI、 cgroup 和 iptables 操作都在已核对 UUID 的获批 VM 内执行。runner 无论成功或失败都尝试 保存日志，确认停止后删除 overlay、seed 和密钥目录；超时 watchdog 提供额外回收路径。

普通检查：

cd reference
go test -race -count=1 -timeout=120s -coverprofile=/tmp/coverage.out -covermode=atomic ./...
go tool cover -func=/tmp/coverage.out
go vet ./...
go build -buildvcs=false ./...

公开协议/接口依据： RFC 7396、 CRI v1.29.0。 此轮未改变第一阶段审计包。

本轮运行结果

最终完整运行目录为 pull-vm（本地工程附件）。 原有 43 项单节点断言及新增 13 项双节点断言全部通过。独立 grader 的单节点 all 为 7 项，带全组件生命周期为 8 项，双节点 all 为 7 项，cross-node 为 2 项；API 恢复模式 另有 2 项。退出后两侧容器/sandbox、IPAM 分配与自有 NAT 规则均已回收。

真实结果包括：1500 毫核 Pod 分别落到两台 2000 毫核节点；双向 PodIP 通信；两个节点的 Pod 经同一 VIP 均访问到两侧后端；9 个 Service 使用不同 VIP；删除后端和重启代理后收敛。

仓库先返回 503，使 Pod 报 RuntimeError；恢复后实际获取唯一镜像层并启动，容器能读取 /pull-proof 的唯一内容；缓存已有该镜像后，仓库再次不可用仍能启动。运行容器中实际读到 cpu.max=5000 100000、memory.max=67108864、pids.max=512、Seccomp=2、CapEff=0x400。 原始文件见 runtime-security.txt（本地工程附件）， 仓库请求见 registry.jsonl（本地工程附件）。

8 个并发客户端创建 100 个独立对象，用时 0.089 秒，UID 全部不同；这是本轮公布的有界 控制面负载实验规模。Go 全套竞态检查通过，语句覆盖率为 84.1%；逐包与逐函数数据保留在 checks（本地工程附件） 与 coverage-functions.txt。 覆盖率按 Go 单元/进程测试统计，fixture main 的真实容器执行另由 VM 断言覆盖。

本轮测试统计：350 个顶层测试、149 个子测试； helper 的条件 skip 和无独立测试的 fixture 包在统计中分别记录。构建、vet、gofmt 均通过。

失败记录与修正

  • first-vm：Service 采样复用了到 VIP 的连接，未完成两个后端的观察，末尾还记录过 502。 fixture /fetch 改为禁用连接复用，让每次样本对应新连接；随后两侧均完成后端采样。 早期 502 没有单独复现定位，原始日志与当时两侧路由/NAT 保留。
  • fresh-vm：双节点网络已通过，测试仓库的方法名 request 与 BaseHTTPRequestHandler 保存的 socket 属性同名，GET 抛 TypeError。改为 serve_image，补独立真实 HTTP 自检， 再用新 VM 通过拉取、恢复、缓存和完整集成；没有跳过失败用例。
  • 首次 Go 检查暴露原有 Allow 断言与资源 map 类型需要随接口修改同步；新增测试曾误用 HTTP 辅助函数的返回类型。修正测试后通过相关检查与完整竞态检查。

交付边界

参考实现现覆盖原教程主线与静态路由跨节点实验，保留本报告列出的架构替换。 普通对象 PATCH 的具体合并协议是对原文缺失 handler 的补充，学习者须按已公布契约实现。 NodePort、DNS、Ingress、CSI/PV/PVC、HPA 与 HA 未纳入本轮。实现与教程的逐章对应见 tutorial/11-independent-validation.md，学习者反馈作为后续改进材料。

CLI 与当前代码规模

kubectl-mini 已在实际独立进程中通过 create/list/get/patch/stale-patch/delete/404/错误资源/help 共 9 项检查；unit 同时验证 replace、文件输入、namespace 与输入限制。 客户端只使用公开 HTTP API，提供给学习者复用。

本轮运行 Go 代码 6,897 行、Go 测试 11,609 行 （cloc 排除空行/注释，fixture 另计）。完整统计见 checks/loc-summary.json。

资源回收与来源

本轮三次实验共 6 台临时 VM 均已停止，临时磁盘、seed、SSH key 与约 357 MiB 的输入缓存 已删除。10 台原有 libvirt VM 仍处于关机状态；清单见 existing-vms-after.log。 第一阶段发布包 SHA-256 保持不变，逐 VM 回收记录见 host-cleanup.json。 一次只读 worker 委派因周额度耗尽退出，服务端确认停止，没有可用调查结果；本轮代码、 复核与测试均由主 agent 执行，记录见 delegation.json。
