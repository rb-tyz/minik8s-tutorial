P01/I01：单节点 MVP 的网络与完整集成

本轮由主 agent 完成，未调用 subagent。按 教学范围 实现原文 §14–15 及相应订正，组合验证已有 Deployment、ReplicaSet、scheduler 与 kubelet。参考实现已在 全新隔离 KVM 通过真实容器和网络验收；修订教程初稿与独立 Bash 测试器均已提供。

实现与材料

  • mini-cni：CNI 0.4.0 ADD/DEL/CHECK/VERSION，文件锁 IPAM、IPv4 bridge/veth、 默认路由、地址释放与复用、失败回收。保留网络、网关、广播地址。
  • mini-proxy：Service VIP 分配与重启恢复、多端口 TCP/UDP、就绪后端、DNAT、 hairpin/SNAT；一次提交自有链，退出撤销自有规则并保留其他链。
  • mini-kubelet --network-mode pod：CRI 网络就绪检查、独立 Pod namespace 与 IP。
  • tutorial/00–10：从对象/控制循环到完整网站更新的修订教程；另有 CRI 操作实验和 学习者复现记录表。公开行为在 docs/contracts/。
  • grader/grade.sh：使用 Bash/curl/jq/公开 API 检查主流程；start/stop/restart 由适配器提供。 grader 自身正例通过，故意把 stale PUT 的 409 错报为 200 的实现被拒绝。

IP 复用故障与订正

早期 I01 曾在最终 Pod/Service 请求失败，初次缺少足够现场；日志原样保存在 evidence/i01-20261107/fresh-vm/。随后增加转发收敛观察，一次通过后， grader-vm/ 再次在 API 停止后的 Service 请求超时，滚动期也记录了两次超时。

最小复现实验 reuse-reproduction/guest/cni-reuse.json 给出了原因： 旧 sandbox 使用 10.246.0.3 / ee:87:3f:5b:71:90，新 sandbox 立即复用该 IP， MAC 变为 9e:6f:ff:f7:fe:f7，而 guest 邻居缓存仍为 REACHABLE 的旧 MAC，请求超时。 这条复现路径与异步 Endpoints 的等待分别处理。

修复为按 IPv4 生成稳定的本地管理单播 MAC（02:00 加四字节 IP），并固定网关 MAC。 IPAM 的地址唯一性也保证本网络内该 MAC 的唯一性。复验中旧/新接口均为 02:00:0a:f6:00:03，地址立即复用后的 HTTP 成功，网关 MAC 稳定。 CNI 单元回归及五轮竞态检查通过；真实复现用例加入每次完整 VM 验收。 网络章节 已补充 ARP、故障原因与可选修复思路。 上游 bridge 同样固定网关 MAC，参见 CNI plugins v1.4.0 bridge.ensureAddr。

reuse-before/ 是新探针把 DEL 空输出当作 JSON 解析的失败，修正探针后才得到上述网络反例。 所有失败目录保留实际结果，每次复验使用新目录。

测试器收尾检查

整理交付时又发现清理误报：功能检查完成后，Service List 若持续返回 503，旧版 cleanup 会跳过该集合并报告成功。新增公开 HTTP 故障适配器复现，记录在 evidence/grader-cleanup-20261107/before/summary.json：功能检查通过，清理结果未知，却退出 0。

现改为轮询确认所有集合均成功返回合法空列表；查询失败或列表格式错误会保留响应并继续 等待，到期限仍未确认则退出非零。grader/verify.py 在普通用户环境复验真实 API CRUD/Watch 正例、错误 CAS 响应和清理查询失败两个负例，结果见 after/summary.json。 这项修订发生在 KVM 集成验收之后，针对测试器的公共 HTTP 清理路径；容器与网络实现未改动。
