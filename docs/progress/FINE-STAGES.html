提交与导航

stage 使用 3.1 形式的编号。普通 submit 只运行当前 stage 的一个检查，通过后进入下一项。 submit --all 从头逐项执行 70 项，失败处停止，保存连续通过的进度。 单个数字 3 是 3.1 的别名；section 3 阅读 KV 小节完整说明。

minik8s stage 3.1
minik8s section 3
minik8s submit
minik8s submit --stage 3.4
minik8s submit --all
minik8s serve

前端以折叠小节组织 stage，显示每节和全课程进度。任务页内可以打开小节原理说明，再返回 当前 stage。服务接口同时提供 sections 与 stages；API 写请求使用字符串 stage 编号。 重复启动同一项目的服务会返回已有服务地址。

测试粒度

新增细分断言位于 grader/steps/，与原有公共断言一起供课程调用。统一目录与映射来自 grader/course/curriculum.py；grader/build-course.py 发布任务页和共享 JSON 清单。 CLI、Bash 与前端使用同一组 ID。

底层课程入口示例：

bash grader/test.sh --stage 3 --step KV-GET \
  --driver /path/to/my-driver --output /tmp/kv-get-new

--step 验证指定的检查 key、单项结果与清理，结果使用 step_complete。 原 test.sh --stage N、--only 和 44 项综合检查保留，综合阶段继续使用 stage_complete。

前置依赖按教学顺序收缩：

  • KV 第一项只调用 put/get；版本、CAS、List、Watch 分别在后续 stage 验收。
  • API 第一项只要求创建与读取。启动探测接受 HTTP 响应；本次独立 API 进程由生命周期 adapter 停止，数据库与请求记录留在测试工作目录，便于复查。
  • CNI ADD 第一项由测试设施回收本次专用 namespace/bridge，后续再验收地址释放与 DEL 语义。 所有网络操作仍在经身份核对的 KVM 内执行。

进度兼容

新进度使用 schema_version=2 和字符串 stage ID。旧版通过一个小节，映射为该节全部 stage 完成；例如旧版完成小节 1/2 后，新版从 3.1 开始。 读取时提供转换视图；第一次保存新版进度前，备份旧文件到 progress.v1.json。 已有备份与运行记录保留，迁移与配置写入共用项目锁。

验证结果

  • 64 项课程/服务测试通过，覆盖分组目录、ID、单项前进、全量停止、迁移备份、错误状态、 取消、项目锁与重复启动服务。
  • 普通用户态验收（本地工程附件）：36 个 stage 全部通过。 只实现 put/get 的程序通过 3.1；只实现创建/读取的 API 通过 4.1。 故意错误的 CAS 转发器在对应的 3.4 被检出。
  • 实际连续提交（本地工程附件）：九次独立 CLI 提交从 3.1 前进到 4.1，旧文件已备份。
  • KVM 全量验收（本地工程附件）：70 个细分 stage 全部通过， 随后原 44 项综合回归全部通过。另完成镜像缓存复验和故意错误 CNI CHECK 检出。
  • 浏览器验收（本地工程附件）：11 个场景通过。 包含分组导航、单项真实 KV 提交、刷新保持进度、小节原理阅读与返回、取消、配置、 全量环境检查，以及空闲/测试期间的阅读稳定性。
  • 桌面与移动截图已检查：桌面（本地工程附件）、 移动（本地工程附件）。浏览器无运行时异常。

首轮 KVM 跑到第 70 项时，函数名校验拒绝 proxy_e2e 中的数字。修正为合法函数名规则后， 重新执行全部 70 项与原 44 项回归。失败记录保留在 fine-kvm-20261108。 两轮共四台临时 VM 均已停止销毁，下载输入在最终通过后删除。

用户预览服务保留在 http://127.0.0.1:7331。测试用服务与延迟 driver 均已停止。 交付文件、校验值与环境清理结果见 最终汇总（本地工程附件）。
