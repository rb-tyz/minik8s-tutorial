R01：ReplicaSet 控制器

mini-controller-manager --server <API地址> 是独立进程，当前运行 ReplicaSet 控制器。 它用 C01 的 Informer/WorkQueue 监听 RS 和 Pod，串行协调副本，通过公开 API 创建、删除 Pod 和更新 RS status。SIGINT/SIGTERM 会取消两个 Informer 并等待退出。

副本归属与动作

控制器读取最新 ReplicaSet，再 List 同 namespace 的 Pod。只有 controller ownerReference 的 APIVersion=apps/v1、Kind=ReplicaSet、Name 与 UID 均匹配，且 Pod labels 满足 RS selector 时才计入该 RS。相同标签的独立 Pod 保持独立；本实现不提供孤儿认领和 selector 变更后的释放。 仍属于当前 RS 但 labels 不匹配的 Pod 保持现状，不计入副本和 ready 统计。 API 在创建/更新 RS 时检查 selector 与 template labels 一致。

  • 活跃副本少于目标：从 template 复制 Pod spec、labels、annotations，设置 ownerReference。
  • 副本过多：按名称降序删除多余 Pod。
  • Succeeded/Failed Pod：回收并补建新 UID 的 Pod。
  • 父 RS 删除或同名重建：重新核对 owner 的实时 UID，清理旧 UID 的子 Pod。
  • 每次最多创建或缩容删除 16 个活跃副本，余量通过队列继续处理。

创建名称由 RS 名称前缀、RS UID 摘要与 slot 确定。创建响应丢失后，下一轮 List 会看到 已提交的 Pod；尚未观察到时也会重试相同名字。409 后重新查询，避免追加随机名字超建。 名称已被无关 Pod 占用时保留该 Pod 并选下一 slot。删除携带 Pod RV，冲突后重新查询， 删除响应丢失后由下一次 List 确认结果。

每轮动作前后都读 API，而非用 Informer 缓存计数；已确认创建/删除可在下一轮被观察到， 无需另建未观察创建的 expectation 账本。Informer 负责触发工作，缓存延迟不改变副本计算。 当前支持一个 controller-manager 进程，无 leader election。

状态

动作后重新 List，报告当前活跃 Replicas、FullyLabeledReplicas、ReadyReplicas 与 AvailableReplicas。Ready 要求 Pod Running，所有应用容器均有状态且 Ready=true； Available 暂与 Ready 相同，没有 minReadySeconds。相同 status 经 API 的 no-op 检查不产生 新版本，防止状态事件反复触发写入。ObservedGeneration 保持零，当前模型尚无 generation 字段。

控制器使用 GET 时的 RS RV 写 status；资源同时改变时返回 409，之后按新 spec 重试。 API 不可用、创建或删除失败时保留任务，并采用队列指数退避；回调中只入队。

运行与验收

cd reference
go build -buildvcs=false -o /tmp/mini-controller-manager ./cmd/mini-controller-manager
/tmp/mini-controller-manager --server http://127.0.0.1:8080
go test -race -count=1 -timeout=60s ./internal/controller ./cmd/mini-controller-manager

普通 HTTP 测试覆盖创建、扩缩容、删除补齐、终止替换、UID 重建、孤儿回收、无关 Pod 保护、 创建与删除响应丢失、slot 冲突、批量限制、status 无变化和进程取消。 隔离 KVM 验收通过真实容器验证两个副本、删除恢复、controller-manager 强杀重启后扩到 3 个、 缩到 1 个，以及父 RS 删除后的 Pod/运行时回收。命令与日志见 N01-R01.md。 Deployment 与 Endpoints 控制器属于下一项 R02。
