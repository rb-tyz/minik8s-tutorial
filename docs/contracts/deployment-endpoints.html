R02：基础 Deployment 与 Endpoints

教学范围对应原文 §13.4–13.5、DEPLOY-002、EPS-001/002，任务说明与逐步验收写在 tutorial/08-deployment-endpoints.md。本轮增加的 订正与实现选择记录于 docs/progress/R02.md，运行日志随交接归档。

controller-manager 在同一个单 worker 中运行三类 reconcile：RS、Deployment、Service。 四个 Informer 分别监听 Pod、RS、Deployment、Service。所有写入使用公开 API 和 CAS； 失败重新入队，每次计算从 API 重新读取。当前支持一个 controller-manager 进程。

Deployment

  • 支持 RollingUpdate；先前类型预留的 Recreate 在本 MVP 返回 422。
  • template hash 标记新 RS 与 Pod，pod-template-hash 为保留 label。
  • surge 百分比向上取整，unavailable 向下取整并封顶为 desired；desired>0 且换算后 两者均为零时返回 422。原版 Kubernetes 在部分取整情形下回退为 unavailable=1， 本 MVP 要求调用方提供可取得进展的参数。
  • 每轮最多修改一个 RS；等待 RS status 反映前一次申请后再继续。未就绪新版保持等待， 就绪预算内缩旧版；旧版未就绪副本可回收以释放容量。
  • 同名父对象以 UID 区分。完成后清除空旧 RS；父 Deployment 删除后按 UID 回收自有 RS。
  • status.replicas 为自有 RS 已观察副本之和；updatedReplicas 为当前 template 的已观察副本； readyReplicas 为已观察就绪数（不超过每个 RS 当前申请数）；availableReplicas 暂与 Ready 相同。
  • 不提供暂停、回滚、进度期限或其他生产 Deployment 状态机。

Endpoints

  • 从同 namespace、匹配 Service selector、Running、所有应用容器 Ready 且 IP 有效的 Pod 生成。
  • 缺省 targetPort 使用 Service port；整数原样使用；字符串按应用容器端口名称与 protocol 解析。
  • 每个 subset 只有一个解析后的端口；后端按该端口分组。排序后比较，内容未变时不写入。
  • 自动 Endpoints 使用 Service owner UID；Service 删除后清理，同名重建时更新归属。
  • selector 为空时保持现状；手工同名 Endpoints 不被覆盖。
  • 本轮验证后端对象生成；Service 的实际网络转发属于 P01。
