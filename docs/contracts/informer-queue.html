C01：Informer 与 WorkQueue

reference/internal/informer 把 HTTP List/Watch 转为可并发读取的缓存； reference/internal/workqueue 为控制器提供按 key 去重的任务队列。两者只使用标准库。

缓存与通知

informer.New(source, resource, namespace, Options) 返回一个单次运行的 Informer。 source 由 *client.Client 实现；namespace 为空时订阅全部 namespace。 Run(ctx) 持续运行到取消，重复调用返回错误。WaitForSync(ctx) 等待首次 List 安装 及其通知完成，HasSynced() 表示曾经完成首次同步。断线时保留上次缓存，同步标志 继续为 true；它表示初始化完成，连接健康需要另行观察错误回调。

  • Get(key) 返回对象副本与存在标志。
  • List() 按 key 排序返回对象副本。
  • ResourceVersion() 返回已应用的游标。
  • Key(obj) 为 namespaced 对象生成 namespace/name，Node 使用 name。
  • Options.OnEvent(Event) 串行接收 ADDED、MODIFIED、DELETED，Old/New 也是副本。 缓存在回调前已更新。回调应快速入队，允许查询缓存；回调中等待本次 Run 退出会阻塞自身。
  • Options.OnError(error) 报告失败；RetryDelay 默认 100ms，重试等待支持取消。

首次 List 原子替换缓存，使用 list RV 作为下一次 Exact Watch 的起点。事件通过校验后， 缓存与游标一起更新。BOOKMARK 推进游标；重复或更旧的帧被忽略。删除、同名重建分别通知， 同名且 UID 改变时先 DELETED 后 ADDED。重新 List 会通知断线期间遗漏的删除和更新； UID 与对象 RV 都未改变时不重复通知。

普通 EOF 或握手连接失败从最后已应用 RV 重连；410、503 和非法事件重新 List。 List 失败保留缓存并重试。每次连接都由 Informer 调用 Watch.Stop()，等待读流结束。 JSON 解码失败终止当前连接并从已应用 RV 重试，重复遇到格式错误会持续上报。

api.ObjectList 增加 GetListMeta() 和 GetObjects()；六种 List 都实现，后者返回副本。 List 对象必须有合法的 snapshot RV，各 item RV 为正且不超过 snapshot RV。

队列与重试

workqueue.New(Options) 创建队列。Add(key) 对等待项去重，同一 key 正在处理时 记录 dirty；Done(key) 之后再提供一次任务。不同 worker 可以并行处理不同 key。 每次成功 Get(ctx) 都应有一次 Done；取消或 shutdown 返回 false。

AddAfter(key, delay) 按最早时间合并定时任务；Add 立即入队并取消该 key 的延迟。 AddRateLimited 增加失败次数，延迟从 100ms 开始倍增，最多 30s，可通过 Options 修改。 Forget 清除失败次数并取消延迟重试。延迟入队不会把正在处理的 key 分给第二个 worker。

for {
    key, ok := queue.Get(ctx)
    if !ok { return }
    if err := reconcile(ctx, key); err != nil {
        queue.AddRateLimited(key)
    } else {
        queue.Forget(key)
    }
    queue.Done(key)
}

ShutDown() 丢弃等待项、取消所有定时器并唤醒 worker；已领取任务的执行与取消由 worker 负责。队列和缓存都保存在进程内，重启后从 API List 重建。

验证

cd reference
go test -race -count=1 -timeout=60s ./internal/informer ./internal/workqueue

单元测试覆盖副本隔离、差异通知、版本校验、去重、重试与退出；HTTP 测试覆盖 List→Watch 间隙写入、EOF 续接、真实 Compact、503 错误帧、同名重建、重新 List 失败与取消。 结果及日志见 C01-S01.md。
