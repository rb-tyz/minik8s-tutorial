6. Kubelet：已绑定 Pod、init、重启与恢复

只启动 API 与 kubelet，手工填写 nodeName。分开验收登记、心跳、节点过滤、实际容器、状态、资源、退出策略、卷、镜像失败、删除、接管和短暂中断。

本节接入

测试器通过启停脚本启动 API 和 kubelet，通过 API 创建测试 Pod，并在需要时填写 spec.nodeName。你的 kubelet 读取绑定到本节点的 Pod，调用 CRI，向 API 写回 Pod.status。测试器从 API 读取状态，部分关卡还用 crictl inspect 核对真实容器。

fixture 是镜像里的应用程序，exit、env、write、require 是它接收的参数。hostPath 指 KVM 节点上的目录；volumeMount.mountPath 是容器内看到的路径。检查容器退出、故障恢复和重启时，区分 fixture 的退出码、Pod 状态和 kubelet 进程的生命周期。

使用 --adapter ./test-hooks --fixture ./lab 接入这个小节。guest 需有可用的 CRI、crictl、测试镜像，镜像恢复关还用本地 registry。镜像与运行时准备
