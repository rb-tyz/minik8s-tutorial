2. CRI：sandbox 与容器生命周期

用同一套公开操作验收 sandbox、创建、启动、列举、退出、镜像与删除。不要求第一关就实现完整的后续清理，删除能力在相应 stage 出现。

本节接入

本节沿用 ./bin/my-minik8s。测试器把操作名和参数传给它；你的程序调用 KVM 内的 CRI 容器运行时（如 containerd），再把结果写成 JSON。Pod sandbox 是一组容器共享的运行环境，sandbox ID 与其中每个应用容器的 ID 各自独立。

每次操作启动一个新进程，并传同一轮的 --state-dir。示例中的 $sid 是前一次 sandbox-run 返回的 id，$cid 是 container-create 返回的 id。命令成功处理业务错误时，命令退出 0、JSON 中 ok 为 false；容器自己的退出码在终态响应的 exitCode 中。

默认命令行接口下，返回运行时给出的 sandbox 或容器 ID。测试器用 crictl 按这些 ID 清理资源，清理脚本接受 12–64 位十六进制字符。container-create 省略 --image 时，使用 MINIK8S_GRADER_IMAGE 指定的基础镜像，默认是 minik8s.local/fixture:n01。各关只需提供当时用到的操作。此节的 guest 需要可用的 CRI 服务、crictl 和测试镜像，2.13 还要能访问本地测试仓库。镜像与运行时准备
