4. API：CRUD、身份、PATCH、status 与 binding

用随机 namespace 验收 HTTP 对象 API。这一节启动独立 API 进程，退出清理只停止进程，不提前要求 List 或 DELETE；后续关卡再逐步使用相应接口。

本节接入

你提供 apiserver，以及 test-hooks/start、stop、restart 三个可执行脚本。在项目中用 minik8s init --adapter ./test-hooks --url http://127.0.0.1:18881 配置它们。测试器调用 ./test-hooks/start apiserver WORKDIR 后，通过 HTTP 检查 API；stop 和 restart 接收相同的组件名和本轮目录。

测试器每轮选择一个 namespace。页面路径中的 NS 代表这个值。Pod 的名字位于 metadata.name，UID 和 resourceVersion 由 apiserver 分配。更新时客户端使用已读到的版本。标有“字段”或省略号的例子只摘录本关关心的内容。PATCH 使用 application/merge-patch+json。

本节结束时测试器通过 stop 结束 API。status、binding 的写入者由测试器扮演，实际 kubelet 和 scheduler 在后面接入。完整 HTTP 对象格式
