9. CNI：ADD/DEL/CHECK、IPAM 与通信

按 CNI 0.4.0 环境变量与 stdin/stdout 调用插件。ADD 早期由测试设施回收本关专用namespace 与 bridge；地址释放和 DEL 在后面的 stage 验收。

本节接入

在项目里用 minik8s init --cni ./bin/my-cni --fixture ./lab 指定你编译好的插件与测试文件。测试器创建 KVM 内的 netns，每次操作执行一次插件。环境变量 CNI_COMMAND 给出 ADD、CHECK 或 DEL，CNI_CONTAINERID 是容器身份，CNI_NETNS 是 netns 路径，CNI_IFNAME 指明接口名。网络配置 JSON 从 stdin 传入，包含 cniVersion、name、type、bridge、vmID、ipam.subnet 和 ipam.stateFile。9.11 会在 netns 内启动课程提供的 lab/rootfs/fixture，编译命令见首次提交指南。

ADD 的结果 JSON 写到 stdout。CHECK 或 DEL 通过进程退出码表示成功或失败，诊断写 stderr。测试器在 guest 内用 ip 和 curl 核对实际状态。9.1–9.6 的 netns 与桥由测试器收尾，9.7 起还会调用你的 DEL。
