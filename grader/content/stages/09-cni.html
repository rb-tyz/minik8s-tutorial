小节 9：连接两个 Pod 的网络

你的任务

在本小节，你要实现一个 CNI 插件，为 Pod 分配 IPv4 地址，连接网络接口并配置路由， 让同一节点上的两个网络 namespace 能够通信。对应教程第 14 节。

一个 Pod 的接口怎样接到另一个 Pod？

每个 Pod 有自己的网络 namespace。可以用一对 veth 连接它与节点：一端放进 Pod， 作为 eth0；另一端接到节点的 bridge。给 Pod 端配置地址和路由后，数据就能经 bridge 到达其他 Pod。

Pod A eth0 ── veth ── bridge ── veth ── Pod B eth0

CNI 通过环境变量提供容器 ID、namespace 路径和操作类型，通过 stdin 提供 JSON 配置。 你的插件执行操作后，把结果 JSON 写到 stdout；诊断日志写到 stderr。

地址分配也有生命周期

IPAM 负责分配和释放地址。同一个容器重复 ADD 时，应能取得原有分配；地址用完时返回错误， 释放后允许其他容器使用。

例如测试使用一个 /30 子网：网络地址和广播地址不可分配，另一个地址留给网关，只剩一个 Pod 地址。这样只需两个容器 ID，就能检查地址耗尽、重复调用与释放复用。

ADD、CHECK 和 DEL

ADD 建立连接，CHECK 检查已有连接是否仍符合配置，DEL 回收连接和地址。 CHECK 需要观察实际接口与路由；如果默认路由被删掉，应当发现问题。

DEL 还会遇到 Pod namespace 已经消失的情况。这时继续释放本次分配，重复执行 DEL 也应成功。 具体调用约定见 CNI 接口。

测试如何运行

测试器在隔离 KVM 中创建本次专用的 namespace、子网与 bridge：

  • CNI-IPAM：地址耗尽、重复 ADD、释放复用及接口回收。
  • CNI-CHECK：完整网络通过，删除默认路由后失败。
  • CNI-DEL：namespace 已消失和重复删除的情况。
  • CNI-TRAFFIC：一个 namespace 中启动 HTTP 程序，从另一个 namespace 实际访问。

提示

先接通一对 namespace，逐项核对地址、接口状态与路由，再加入地址记录和重复调用处理。 可以先记录某个容器 ID 对应的地址，失败时按已经完成的步骤回收资源。

按 stage 提交

本小节分为 5 个 stage。先查看第一项任务：

minik8s stage 9.1

正常学习时逐项执行 minik8s submit，每次只验收当前一项能力。 临时练习时指定完整编号，例如：

minik8s submit --stage 9.1
