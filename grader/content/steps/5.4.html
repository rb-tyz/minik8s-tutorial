Stage 5.4：发送完整删除事件

你的任务

让实时删除事件保留对象内容，并使用删除提交的版本。

程序怎样被调用

本阶段继续运行 API 服务。测试器用 HTTP 建立 Watch 长连接，再从另一个连接创建或删除对象。 Watch 表示持续订阅对象变化；返回格式是 NDJSON，即每行一个 JSON 事件。

本页 URL 使用 demo 作为 namespace 示例。一个事件中的 type 表示变化类型，object 是对应 对象。resourceVersion 是对象或快照的存储版本，用于说明从哪里接收后续变化。 API 的启动和停止仍使用 --adapter 指定的脚本目录。

删除后还需要旧对象

测试器先建立带初始快照的 Watch，等到 BOOKMARK 后删除已有 Pod。流中应收到：

{"type":"DELETED","object":{"metadata":{"name":"initial","uid":"pod-a","resourceVersion":"11"},"spec":{"containers":[{"name":"app","image":"minik8s.local/fixture:n01"}]}}}

响应保留被删对象的 UID 和 spec，版本对应删除这次提交。客户端据此从本地缓存移除正确的 生命周期，避免把同名重建的对象一并处理。

实现思路

从 KV 删除事件携带的旧值构造 object，同时填入事件的提交版本。发送完整的一行后刷新连接。 继续保留先 ADDED、后 BOOKMARK、再实时事件的顺序。

测试方式

WATCH-INITIAL：初始同步后收到 DELETED，UID、spec 和镜像字段完整。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
