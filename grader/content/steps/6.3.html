Stage 6.3：上报退出码与终态

你的任务

处理 Never 策略下的应用退出。

程序怎样被调用

本阶段实现 kubelet，也就是在一个节点上负责运行 Pod 的组件。Pod 是对“运行哪些容器”的描述： spec 保存期望配置，status 保存观察结果。kubelet 读取分配给本节点的 Pod，调用前两节的 运行时接口，再把结果写回 API。

测试器调用 ./test-hooks/start node /tmp/course-run/work/lifecycle，由你的脚本启动 API 和 kubelet。随后它创建已经填写 spec.nodeName 的 Pod，并等待结果。这里使用节点网络，Pod 网络 在第九小节实现。本节在实验 KVM 内运行，测试程序和镜像由实验环境准备。

把应用失败保存下来

输入 Pod 的相关字段是：

{"restartPolicy":"Never","containers":[{"name":"app","image":"minik8s.local/fixture:n01","command":["/fixture"],"args":["exit","42"]}]}

测试程序会退出 42。测试器轮询这个 Pod，要求 status.phase=Failed，并在 status.containerStatuses[0].exitCode 中读到 42。

实现思路

先从运行时读取应用的终态与退出码。Never 策略下保留这次结束记录，写回 Pod 状态。 一次调谐结束后，后续轮询应继续看到这份终态，方便用户查询任务为什么结束。
