Stage 4.5：合并局部更新

你的任务

支持 JSON Merge Patch 的对象、null 和数组语义。

程序怎样被调用

从本小节开始，测试器通过 HTTP 请求访问你写的 API 服务。API 服务是一个监听端口的程序， 负责把请求转换为上一小节的 KV 操作。测试器通过启动脚本运行它，例如：

./test-hooks/start apiserver /tmp/course-run/work/lifecycle

start 是你提供的脚本文件，apiserver 是第一个参数，表示启动 API；第二个参数是本轮数据与 日志目录。--adapter ./test-hooks 告诉测试器去哪里找这些脚本。具体约定见 启动、停止和重启。

本页用 demo 表示测试 namespace。namespace 是对象名称的分组，同名 Pod 可以出现在不同分组。 实际测试会随机生成这个分组名，API 根据收到的 URL 处理。

PATCH 只发送要改变的部分

JSON Merge Patch 用来合并局部更新。测试器创建带 labels.app 的 Pod，再发：

PATCH /api/v1/namespaces/demo/pods/patched
Content-Type: application/merge-patch+json

{"metadata":{"resourceVersion":"7","labels":{"app":null,"patched":"yes"}}}

这里的 7 使用刚读到的真实版本替换。null 表示删除 app 标签，patched=yes 表示新增标签。 成功返回 200，UID 与其他字段保留，版本改变。原请求再发一次时，旧版本应得到 409。

实现思路

对象字段递归合并；null 删除对应字段；数组整体替换。合并后再检查身份和版本，并通过 CAS 提交。保持调用方没有提到的 spec 等字段，避免局部修改丢失整份对象内容。

测试方式

API-PATCH：递归合并、字段删除和版本保护均符合已公布的 API 行为。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
