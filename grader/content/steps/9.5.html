Stage 9.5：在两个 Pod 网络间通信

你的任务

让两个独立 namespace 中的程序经 Pod IP 通信。

程序怎样被调用

CNI 是运行时为容器配置网络的调用约定。本节需要一个可执行网络程序，用 --cni 指定。 它每次处理一次调用：从环境变量读取操作类型和目标，从 stdin 读取一份配置 JSON，完成后退出。 这与前三节持续读取多行请求的程序不同。

测试器会在实验 KVM 内创建本轮独占的网络 namespace（一套独立网络视图），把它的路径放进 CNI_NETNS，接口名称放进 CNI_IFNAME，容器身份放进 CNI_CONTAINERID。诊断写 stderr； ADD 成功时 stdout 返回 CNI JSON 结果，成功退出码为 0。字段例子见 CNI 调用。

最后用真实流量检查

测试器创建两个独立网络 namespace，用你的 ADD 配置同一网段的地址。它在第一端运行 提供的 fixture，参数为 http :8080；第二端向第一端的 Pod IP 发 HTTP 请求。

预期 HTTP 成功，响应正文为 minik8s-container。这里使用 fixture 自带的 HTTP 模式， 你继续实现网络连接，应用程序由环境提供。

实现思路

确认两端 eth0 都已启用，地址属于本轮子网，veth 节点侧连到同一 bridge。先检查每一端的 地址和路由，再沿报文经过的接口排查连接。原文双节点静态路由另有补充实验入口。
