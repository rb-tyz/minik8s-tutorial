Stage 8.4：删除父对象并回收子对象

你的任务

在 ReplicaSet 删除后回收其自有 Pod。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

父对象删除后的处理

本项会复用前面几步：创建独立同标签 Pod、创建两个自有副本、删除一个自有副本并等待补齐。 随后删除 ReplicaSet：

DELETE /apis/apps/v1/namespaces/demo/replicasets/replicas

测试器按原 ReplicaSet UID 列举子 Pod，等待自有集合变空，并确认独立 Pod 仍可 GET。

实现思路

在观察到父对象删除时，根据父 UID 找到本课程中需要回收的自有 Pod。保留独立对象， 逐个完成删除。父对象已经不存在时，也要有路径处理先前留下的子对象记录。

测试方式

CTRL-RS：父对象删除后自有 Pod 消失，独立 Pod 保留。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
