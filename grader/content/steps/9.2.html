Stage 9.2：分配、耗尽与复用地址

你的任务

为容器身份保存分配记录，处理重复 ADD、耗尽与释放复用。

程序怎样被调用

CNI 是运行时为容器配置网络的调用约定。本节需要一个可执行网络程序，用 --cni 指定。 它每次处理一次调用：从环境变量读取操作类型和目标，从 stdin 读取一份配置 JSON，完成后退出。 这与前三节持续读取多行请求的程序不同。

测试器会在实验 KVM 内创建本轮独占的网络 namespace（一套独立网络视图），把它的路径放进 CNI_NETNS，接口名称放进 CNI_IFNAME，容器身份放进 CNI_CONTAINERID。诊断写 stderr； ADD 成功时 stdout 返回 CNI JSON 结果，成功退出码为 0。字段例子见 CNI 调用。

每次调用都是一个新进程

IPAM 指 IP 地址分配与释放。程序退出后，下一次调用仍需根据容器 ID 找到原分配， 因此可以利用输入中的 stateFile 保存记录。

测试网段是 10.249.0.0/30：.0 为网络地址，.3 为广播地址，.1 留给网关，只有 .2 可给 Pod。 测试顺序是：为第一个 ID ADD，重复 ADD 同一 ID，为第二个 ID ADD，DEL 第一个 ID，再为第二个 ADD。

预期前两次都返回 10.249.0.2/30；地址耗尽时第二个 ID 的 ADD 非零退出；释放后它能取得 .2。 第一次 DEL 还应移除原 namespace 中的 eth0。

实现思路

把 ID 与地址对应起来，分配时先查询已有记录，再挑选可用地址。释放时移除本轮网络连接 和地址占用，并保存更新后的记录。文件格式由你选择，测试通过调用结果与实际接口观察。
