Stage 5.3：接续 List 与 Watch

你的任务

通过 HTTP 从 List 的快照版本续接变化。

程序怎样被调用

本阶段继续运行 API 服务。测试器用 HTTP 建立 Watch 长连接，再从另一个连接创建或删除对象。 Watch 表示持续订阅对象变化；返回格式是 NDJSON，即每行一个 JSON 事件。

本页 URL 使用 demo 作为 namespace 示例。一个事件中的 type 表示变化类型，object 是对应 对象。resourceVersion 是对象或快照的存储版本，用于说明从哪里接收后续变化。 API 的启动和停止仍使用 --adapter 指定的脚本目录。

建立连接前的那次写入

测试器先 GET Pod 列表，记住顶层快照版本；在 Watch 建立前再创建 replay。接下来请求：

GET /api/v1/namespaces/demo/pods?watch=true&resourceVersion=10

10 用实际 List 返回的位置替换。即使 replay 在连接开始前已经创建，流中仍应补发它的 ADDED， 并携带创建时的真实 UID。

实现思路

把 HTTP 的 resourceVersion 传给 KV Watch，从该版本之后重放匹配事件，再进入实时等待。 一个集合的事件只覆盖对应 namespace 和资源类型。
