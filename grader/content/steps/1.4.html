Stage 1.4：根目录不存在时让 container-run 报错退出

测试器故意把一个不存在的目录传给 --rootfs。里面的 fixture exit 0 无法启动，你的 my-minik8s container-run 应向 stderr 写出原因，自己以非零状态退出。

测试方式

测试器在本轮工作目录中选取一个不存在的 missing-root。默认命令行接口下，my-minik8s 应返回非零退出码，且 stdout 不输出成功 JSON。具体非零数值和 stderr 措辞由实现决定。

# 在测试用的 KVM 内，假设 work/missing-root 不存在
./bin/my-minik8s container-run --state-dir work/driver --rootfs work/missing-root \
  --nonce run-a --wait true --arg=exit --arg=0 --cgroup-parent "$parent"
# stderr 示例：启动 fixture 失败：work/missing-root 不存在
# stdout 为空
echo "$?"    # 示例：1，这是 my-minik8s 自己的退出码

实现思路

--arg=exit --arg=0 是准备交给 fixture 的参数。只有 fixture 启动后，这个 0 才有机会成为它的退出码。

情况 fixture 发生了什么 my-minik8s 自己的退出码 my-minik8s 的 stdout
1.3：正常 rootfs，要求执行 exit 42 已启动，随后退出 42 0 {"ok":true,"exitCode":42}
1.4：rootfs 不存在，要求执行 exit 0 未启动，没有任务退出码 非零，例如 1 可以留空

如果你的实现另起子进程准备根目录，它启动失败时也要把错误传回 container-run，让这个命令退出非零。只有 fixture 确实运行并结束，才把它的退出码填进 JSON。
