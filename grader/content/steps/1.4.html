Stage 1.4：限制 CPU、内存与进程数

你的任务

把容器任务加入独立 cgroup，并应用输入的资源限制。

程序怎样被调用

测试器会把你编译的程序作为一个长期运行的子进程启动。例如：

./bin/my-minik8s /tmp/course-run/work/driver

./bin/my-minik8s 是你的程序；后面的路径是测试器分配给这一轮的工作目录，在 Go 中通过 os.Args[1] 读取。测试器把一行 JSON 写进你的标准输入（stdin），你的程序处理后向标准输出 （stdout）写一行 JSON。调试日志写到标准错误（stderr）。接入选项 --driver 指向的就是这个程序。

本小节的正式提交在获批的实验 KVM 内执行。测试程序与目录的准备见 从空 main 到第一次提交。

资源数字怎样落到内核

这次仍启动 pause 后台任务。请求中的资源字段为：

{"cpu":50,"memory":67108864,"pids":512}

cpu 使用毫核，50 表示 0.05 个核；memory 使用字节，67108864 是 64 MiB；pids 限制任务中 可创建的进程/线程数量。cgroup 是 Linux 给一组进程记账和设置配额的机制。

测试器从 /proc/<pid>/cgroup 找到任务实际所属的 cgroup，再读取其 cgroup v2 文件：

cpu.max    → 5000 100000
memory.max → 67108864
pids.max   → 512

CPU 的两个数表示每 100000 微秒周期最多运行 5000 微秒。返回 JSON 仍是 ok、id、pid，配额 通过实际内核文件检查。

实现思路

为本轮任务创建独立 cgroup，设置限制并把任务加入其中。可以在 runc 配置中传入这些限制。 沿用 1.2 的进程记录，reset 时先结束任务，再回收本轮 cgroup。

测试方式

CONTAINER-CGROUP：cpu.max 为 5000 100000，memory.max 为 67108864，pids.max 为 512。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
