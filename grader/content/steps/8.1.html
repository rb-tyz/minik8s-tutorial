Stage 8.1：根据模板创建副本

你的任务

让 ReplicaSet 控制器按期望数量创建 Pod。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

父对象怎样描述两个副本

ReplicaSet 是“按同一份模板维持指定数量 Pod”的对象。测试器 POST 到 /apis/apps/v1/namespaces/demo/replicasets，相关配置为：

{"metadata":{"name":"replicas"},"spec":{"replicas":2,"selector":{"matchLabels":{"app":"replicas"}},"template":{"metadata":{"labels":{"app":"replicas"}},"spec":{"containers":[{"name":"app","image":"minik8s.local/fixture:n01","args":["pause"]}]}}}}

replicas 是期望数量，template 是创建 Pod 时使用的模板，selector 用来匹配标签。测试器 随后查询 Pod 列表，要求两个 Pod 的 ownerReferences 指向刚创建的 ReplicaSet UID。

实现思路

读取父对象和已有子对象，计算还缺几个，再按模板创建并添加父对象引用。可以先周期性 List 做一轮调谐。后续用 Informer 先 List 再 Watch 维护本地观察；WorkQueue 保存待处理的父对象 名称，相同名称可合并，失败后再排队重试。

本小节的原理与接口说明

测试方式

CTRL-CREATE：replicas=2 时出现两个带 owner UID 的 Pod。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
