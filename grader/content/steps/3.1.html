Stage 3.1：写入和读取一个键

你的任务

实现 put 和 get，支持读取已有值以及覆盖写入。

程序怎样被调用

本小节验收你的键值存储。测试器启动 --driver 指向的可执行程序，把本轮数据目录作为 os.Args[1] 传入，然后不断往 stdin 写单行 JSON。你从消息的 op 字段判断操作，向 stdout 返回一行 JSON；同一个进程中的多次请求应操作同一份存储。 需要保存数据时，先用 os.MkdirAll 创建传入的目录。

例如 ./bin/my-minik8s /tmp/course-run/work/driver 表示启动你的程序，并把这个目录交给它保存数据。 本阶段可在普通用户环境运行。程序收到 close 后清理并正常结束。 接入说明 解释完整消息格式。

第一组输入和输出

KV 是 key/value（键/值）存储。key 用来找到一条数据，value 保存它的内容。测试器会连续发送：

{"op":"put","key":"basic","value":"one"}
{"op":"get","key":"basic"}
{"op":"put","key":"basic","value":"two"}
{"op":"get","key":"basic"}

put 要把数据保存到当前存储；get 要返回这个键已有的值。第二条响应应包含：

{"ok":true,"entry":{"key":"basic","value":"one"}}

第四条的 value 应变成 two。entry 是返回的一条记录，本阶段读取它的 value；版本字段在 3.3 加入验收。同一进程要处理多条请求，直到收到 close。

实现思路

先用一个 map 保存键和值，put 写入或覆盖，get 查找。将这层操作接到 main 的 JSON 消息分派。 存储可以封装成自己的 Go 类型，测试器通过你的进程输入输出访问它。

测试方式

KV-GET：写入 one 后读到 one，覆盖为 two 后读到 two。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
