Stage 4.9：重启后保留对象身份

你的任务

让 API 重启后继续读取原有存储目录。

程序怎样被调用

从本小节开始，测试器通过 HTTP 请求访问你写的 API 服务。API 服务是一个监听端口的程序， 负责把请求转换为上一小节的 KV 操作。测试器通过启动脚本运行它，例如：

./test-hooks/start apiserver /tmp/course-run/work/lifecycle

start 是你提供的脚本文件，apiserver 是第一个参数，表示启动 API；第二个参数是本轮数据与 日志目录。--adapter ./test-hooks 告诉测试器去哪里找这些脚本。具体约定见 启动、停止和重启。

本页用 demo 表示测试 namespace。namespace 是对象名称的分组，同名 Pod 可以出现在不同分组。 实际测试会随机生成这个分组名，API 根据收到的 URL 处理。

重启的是整个 API 进程

测试器创建 restart 并保存返回的 UID 与 resourceVersion，然后调用：

./test-hooks/restart apiserver /tmp/course-run/work/lifecycle

restart 是你提供的重启脚本。它应结束本次 API 进程，再用相同数据目录启动新进程。 测试器等待 API 重新响应，然后 GET 原 Pod，要求对象、UID 与版本都保留。

实现思路

把工作目录里的持久数据与进程生命周期分开。重启脚本重新传入原存储路径，API 启动时 打开已有 KV 数据。对象 UID 在创建时生成并存储，恢复读取时继续使用它。

测试方式

API-RESTART：原对象、UID 和 resourceVersion 均保留。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

提交代码

当前进度位于本阶段时执行：

minik8s submit

临时练习本阶段，保留课程进度：

minik8s submit --stage 4.9
