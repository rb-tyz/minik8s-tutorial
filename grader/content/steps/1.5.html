Stage 1.5：收紧系统调用与权限

你的任务

为容器启用 seccomp，并将有效 capability 限制为 NET_BIND_SERVICE。

程序怎样被调用

测试器会把你编译的程序作为一个长期运行的子进程启动。例如：

./bin/my-minik8s /tmp/course-run/work/driver

./bin/my-minik8s 是你的程序；后面的路径是测试器分配给这一轮的工作目录，在 Go 中通过 os.Args[1] 读取。测试器把一行 JSON 写进你的标准输入（stdin），你的程序处理后向标准输出 （stdout）写一行 JSON。调试日志写到标准错误（stderr）。接入选项 --driver 指向的就是这个程序。

本小节的正式提交在获批的实验 KVM 内执行。测试程序与目录的准备见 从空 main 到第一次提交。

限制权限的两个入口

seccomp 用来过滤进程可以使用的系统调用；capability 把部分管理员权限拆成独立能力。 本阶段要求启用 seccomp，并只保留 NET_BIND_SERVICE，这项能力允许监听低于 1024 的端口。

测试器仍发 pause 后台任务，然后读取该 PID 的 /proc/<pid>/status，预期有：

Seccomp: 2
CapEff:  0000000000000400

Seccomp=2 表示过滤模式。CapEff 是有效 capability 的位图，0x400 对应本阶段保留的能力。 这些值来自任务进程的实际状态。

实现思路

沿用已经建立的隔离和资源配置，在启动任务时应用 seccomp 与 capability 设置。使用 runc 时把它们放入运行配置，并在 VM 中检查目标 PID 的状态。任务创建失败时，把失败作为操作 错误返回；创建成功后继续支持 reset 和 close。

测试方式

CONTAINER-SECURITY：Seccomp=2，CapEff=0x400。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
