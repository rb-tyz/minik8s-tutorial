Stage 1.5：分开 fixture 的输出和 my-minik8s 的 JSON

测试器会调用你编译的 ./bin/my-minik8s，也就是 --driver 指定的程序。它要启动课程自带的 fixture read 文件名，让 fixture 把文件内容写到自己的 stdout。你的任务是分开两份输出：fixture 打印文件内容，my-minik8s 的 stdout 只写给测试器的 JSON。

测试方式

测试器把 my-minik8s 的 stdout 解析为单个 JSON 对象，检查 ok:true、exitCode:0。文件中的标记出现在 JSON 前后或字段里，都会导致失败。

# 假设测试器在 lab/rootfs/tmp/output-run-a.txt 中写入 PROTOCOL-NOISE-run-a
./bin/my-minik8s container-run --state-dir work --rootfs lab/rootfs \
  --cgroup-parent "$parent" --nonce run-a --wait true \
  --arg=read --arg=tmp/output-run-a.txt
# my-minik8s 的 stdout
{"ok":true,"exitCode":0}

实现思路

启动 fixture 时，把它的 stdout 接到 my-minik8s 的 stderr 或日志文件。例如 Go 的 cmd.Stdout = os.Stderr。my-minik8s 在自己的 stdout 上写 JSON；测试器对日志文件名没有要求。
