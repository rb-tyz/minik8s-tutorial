Stage 1.1：启动任务并取得退出码

你的任务

处理一条执行请求，运行提供的测试程序，并回复真实退出码。

程序怎样被调用

测试器会把你编译的程序作为一个长期运行的子进程启动。例如：

./bin/my-minik8s /tmp/course-run/work/driver

./bin/my-minik8s 是你的程序；后面的路径是测试器分配给这一轮的工作目录，在 Go 中通过 os.Args[1] 读取。测试器把一行 JSON 写进你的标准输入（stdin），你的程序处理后向标准输出 （stdout）写一行 JSON。调试日志写到标准错误（stderr）。接入选项 --driver 指向的就是这个程序。

本小节的正式提交在获批的实验 KVM 内执行。测试程序与目录的准备见 从空 main 到第一次提交。

先认识测试程序

课程提供一个很小的程序，源码在 grader/fixtures/process.go。fixture 在这里表示“供测试使用的 固定程序”。它可以按命令行参数退出、暂停或提供 HTTP 响应，你不用把它的功能写进自己的 main。

假设提供的目录是 /tmp/minik8s-lab/rootfs，实际文件就是：

/tmp/minik8s-lab/rootfs/fixture

rootfs 表示准备作为容器根目录的文件夹。后续把它设置为容器的 / 后，同一个文件在容器里 就叫 /fixture。1.1 先练习启动进程并取得退出码，可以按传入的 rootfs 找到该文件；根目录和 PID 隔离从 1.2 开始验收。

测试器会发什么

第一条消息如下；路径和标记在正式测试中由本轮环境生成：

{"op":"container-run","rootfs":"/tmp/minik8s-lab/rootfs","args":["exit","42"],"nonce":"run-a","resources":{"cpu":50,"memory":67108864,"pids":512},"wait":true}

op 是操作名称。container-run 约定你的程序启动一次任务。args 是传给 fixture 的参数， 这里要求运行 fixture exit 42。wait:true 要求等待它结束，再返回结果。nonce 是本轮标记， resources 是后续资源限制阶段使用的配置；本阶段检查启动、等待和退出码。

fixture 的 exit 42 模式调用 os.Exit(42)。因此预期响应是：

{"ok":true,"exitCode":42}

ok:true 表示执行和等待这次请求已经完成；exitCode 是子任务的结果。你的父程序还要继续 读取请求。测试器接着发送以下两条消息：

{"op":"reset"}
{"op":"close"}

reset 要清理本轮创建的任务，完成后回复 {"ok":true}。close 要清理并结束你的程序，父程序 退出码应为 0；测试器不会再等待它的消息响应。

实现思路

在 main 中循环读取 stdin，每次解析一行 JSON，再按 op 分派处理。启动任务可以从 Go 的 os/exec 开始：根据 rootfs 和 fixture 拼出实际路径，将 args 作为参数，启动并等待。 读取子任务的退出码后编码成单行 JSON。子程序非零退出时，Wait 会返回错误，其中仍携带 实际退出码；把这个结果传回来，父程序继续处理 reset 与 close。

先按 第一次提交的准备步骤 编译自己的程序和 fixture， 在终端手动输入上面的消息，确认能完成一次对话，再运行正式提交。

测试方式

CONTAINER-EXIT：任务退出后返回 exitCode=42，reset 能结束本次资源。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
