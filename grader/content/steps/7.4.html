Stage 7.4：按使用比例评分

你的任务

对能容纳任务的节点按占用比例评分。

程序怎样被调用

本小节实现 scheduler（调度器）：给尚未填写 spec.nodeName 的 Pod 选择节点，并通过 API 的 绑定操作写入选择结果。测试器调用 start scheduler 数据目录，由启动脚本运行 API 与调度器。

测试器通过 HTTP 提供 Node 与 Pod 对象，再观察 Pod 的绑定结果。本节可在普通用户环境运行； 节点状态由测试输入提供，容器的实际运行由后续集成测试验证。CPU 数字使用毫核，1000 表示一个核； 内存数字使用字节。

用比例比较大小不同的节点

测试器提供一个 10000 毫核节点和一个 1000 毫核节点。先放一份已绑定的 5000 毫核 Pod 到 大节点，再提交 100 毫核的新 Pod。

大节点：CPU 已用 50%
小节点：CPU 已用 0%

两个节点都能放下新任务，课程评分规则应优先选择占用比例更低的小节点。

实现思路

在过滤之后计算资源使用比例，再选择分数更好的节点。沿用前面按已绑定 Pod 算出的占用， 避免把剩余绝对数量当作占用比例。最终仍通过带版本保护的 binding 写入分配结果。

测试方式

SCHED-SCORE：宽节点已用一半、窄节点空闲时，选择窄节点。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
