Stage 4.3：按版本替换对象

你的任务

实现 PUT，用当前版本提交替换，并拒绝旧版本。

程序怎样被调用

从本小节开始，测试器通过 HTTP 请求访问你写的 API 服务。API 服务是一个监听端口的程序， 负责把请求转换为上一小节的 KV 操作。测试器通过启动脚本运行它，例如：

./test-hooks/start apiserver /tmp/course-run/work/lifecycle

start 是你提供的脚本文件，apiserver 是第一个参数，表示启动 API；第二个参数是本轮数据与 日志目录。--adapter ./test-hooks 告诉测试器去哪里找这些脚本。具体约定见 启动、停止和重启。

本页用 demo 表示测试 namespace。namespace 是对象名称的分组，同名 Pod 可以出现在不同分组。 实际测试会随机生成这个分组名，API 根据收到的 URL 处理。

PUT 携带读到的版本

测试器创建 replace，读取完整对象，给 metadata.labels 加上 changed=yes，再向同一对象路径 PUT 整个对象。labels 是附在对象上的字符串键值标签。

PUT /api/v1/namespaces/demo/pods/replace

请求保留刚读到的 UID、resourceVersion 和 spec。成功响应为 HTTP 200，UID 保留，版本增大， 标签 changed=yes。随后测试器再次发送旧对象，此时应返回 HTTP 409，表示版本冲突。

实现思路

把请求的 resourceVersion 转成 KV 的 CAS 前置条件。校验 URL 与对象身份，构造替换值后 原子提交。给调用方返回提交后的新版本，供它下一次修改使用。

本小节的原理与接口说明

测试方式

API-REPLACE：有效替换保留 UID 并增加版本，旧版本返回 409。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

提交代码

当前进度位于本阶段时执行：

minik8s submit

临时练习本阶段，保留课程进度：

minik8s submit --stage 4.3
