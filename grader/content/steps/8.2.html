Stage 8.2：补回被删除的副本

你的任务

删除一个受控 Pod 后，重新补齐副本。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

删除后要补出新的对象

测试器先按 8.1 创建两个自有 Pod，选择其中一个，记下它的 name 和 uid，再 DELETE 该 Pod。 它继续列举属于原 ReplicaSet UID 的 Pod，等待数量恢复为两个，并要求旧 Pod UID 不再出现。

新副本可以复用名称，也可以使用新名称；对象生命周期需要新的 UID。测试器按归属与身份 观察结果。

实现思路

在子对象变化后重新调谐父对象，以当前活跃子对象数量计算差额。创建成功后再次观察， 让一次失败或重试不会额外制造多份副本。

本小节的原理与接口说明

测试方式

CTRL-REPLACE：数量恢复为两个，被删对象的 UID 不再出现。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

提交代码

当前进度位于本阶段时执行：

minik8s submit

临时练习本阶段，保留课程进度：

minik8s submit --stage 8.2
