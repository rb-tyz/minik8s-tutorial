Stage 8.3：区分归属与标签

你的任务

识别真正属于 ReplicaSet 的 Pod。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

标签匹配和父子归属各管什么

labels 是对象上的普通键值标签，例如 app=replicas。ownerReferences 则声明它属于哪个 控制器对象。测试器先创建一个只有相同标签、没有父对象引用的独立 Pod，再创建 replicas=2 的 ReplicaSet。

两个受控 Pod 应具有类似的引用：

{"ownerReferences":[{"apiVersion":"apps/v1","kind":"ReplicaSet","name":"replicas","uid":"rs-a","controller":true}]}

这是 metadata 中的字段。测试器核对真实父 UID、类型与 controller 标记，并确认独立 Pod 仍保留自己的 UID，ownerReferences 仍为空。

实现思路

按本课程约定，只把 owner UID 匹配的活跃 Pod 计入受控副本。标签用于模板匹配和查询， 父引用用于识别生命周期归属。创建新副本时附上完整引用。
