Stage 4.1：创建并查询 Pod

你的任务

通过 POST 创建 Pod，再按名称 GET 它。

程序怎样被调用

从本小节开始，测试器通过 HTTP 请求访问你写的 API 服务。API 服务是一个监听端口的程序， 负责把请求转换为上一小节的 KV 操作。测试器通过启动脚本运行它，例如：

./test-hooks/start apiserver /tmp/course-run/work/lifecycle

start 是你提供的脚本文件，apiserver 是第一个参数，表示启动 API；第二个参数是本轮数据与 日志目录。--adapter ./test-hooks 告诉测试器去哪里找这些脚本。具体约定见 启动、停止和重启。

本页用 demo 表示测试 namespace。namespace 是对象名称的分组，同名 Pod 可以出现在不同分组。 实际测试会随机生成这个分组名，API 根据收到的 URL 处理。

从一条 HTTP 请求开始

Pod 是一份容器运行描述。metadata 保存名称和身份，spec 保存想运行的程序。本阶段先把它 作为 API 中的一条记录，实际容器运行在第六小节完成。

测试器向集合路径发送 POST。例如：

POST /api/v1/namespaces/demo/pods
Content-Type: application/json

{"metadata":{"name":"create"},"spec":{"nodeName":"","containers":[{"name":"app","image":"minik8s.local/fixture:n01","command":["/fixture"],"args":["pause"],"resources":{"cpu":50,"memory":67108864}}]}}

image 是镜像名称，command/args 描述容器以后要执行的程序。API 创建成功时返回 HTTP 201， 响应中有完整对象，并新增 metadata.uid 与 metadata.resourceVersion。UID 区分对象的生命周期， resourceVersion 是它当前的存储版本，使用数字字符串。

接着 GET /api/v1/namespaces/demo/pods/create，应返回 HTTP 200、相同 UID、相同版本和原 spec。 本项只测试这两个操作；测试器最后调用 stop 结束本轮独立 API 进程。

实现思路

先解析集合路径与对象路径，把对象编码后写入 KV。读取时填回存储版本，并返回 JSON。 通过启动脚本管理这次 API 进程；本阶段的启动探测接受根路径的 404 响应，尚未实现其他 资源的 List 也能开始练习。

测试方式

API-CREATE：POST 返回 201，GET 返回同一 UID 和版本。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

minik8s submit
