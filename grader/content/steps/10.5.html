Stage 10.5：更新一组可用后端

你的任务

让新连接到达多个后端，并在后端删除后继续服务。

程序怎样被调用

本小节实现 Service Proxy。Service 给一组 Pod 提供固定的虚拟 IP（ClusterIP）；Endpoints 列出当前可用的 Pod 地址和端口。Proxy 读取这两种对象，在节点上维护转发规则。

测试器调用 start all 数据目录，由脚本启动 API、kubelet、scheduler、控制器和 Proxy。 随后它创建对象、等待真实容器就绪，再向 Pod IP 或 Service IP 发送请求。本节在实验 KVM 内运行。 本文地址用于展示数据关系，程序按实际对象中的地址和端口生成规则。

从当前后端生成规则

测试器创建两个 Pod，分别返回 alpha 和 beta，再创建选择它们的 Service。它重复建立新 HTTP 连接，按响应标记确认两个后端都能到达。

随后删除 alpha，等待 Endpoints 只剩一个地址，再读取 iptables 的实际规则，要求已经 撤下指向旧 Pod IP 的 DNAT，并继续请求 Service，期望得到 beta。

实现思路

为新连接选择一个当前后端，后端集合变化后重建对应规则。以新 Endpoints 为准撤下离开的 地址，保留仍有效的目标。测试通过多次新连接采样观察覆盖情况。

测试方式

PROXY-BALANCE：连接样本覆盖两个标记；删除一个后，剩余后端继续可用。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
