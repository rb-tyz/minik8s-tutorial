Stage 4.8：把 Pod 绑定到 Node

你的任务

支持绑定子资源，检查目标 Node 和 Pod 当前版本。

程序怎样被调用

从本小节开始，测试器通过 HTTP 请求访问你写的 API 服务。API 服务是一个监听端口的程序， 负责把请求转换为上一小节的 KV 操作。测试器通过启动脚本运行它，例如：

./test-hooks/start apiserver /tmp/course-run/work/lifecycle

start 是你提供的脚本文件，apiserver 是第一个参数，表示启动 API；第二个参数是本轮数据与 日志目录。--adapter ./test-hooks 告诉测试器去哪里找这些脚本。具体约定见 启动、停止和重启。

本页用 demo 表示测试 namespace。namespace 是对象名称的分组，同名 Pod 可以出现在不同分组。 实际测试会随机生成这个分组名，API 根据收到的 URL 处理。

绑定操作写入哪个字段

Node 对象表示一个节点；Pod.spec.nodeName 记录 Pod 被分给哪个节点。Binding 是提交分配结果 的消息。本阶段测试器先创建两个 Node 和一个未绑定 Pod，然后发送：

POST /api/v1/namespaces/demo/pods/binding/binding

{"apiVersion":"v1","kind":"Binding","metadata":{"name":"binding","namespace":"demo","uid":"pod-a","resourceVersion":"7"},"target":{"kind":"Node","name":"node-a"}}

最后一段 /binding 是子资源，前面的 binding 是本例 Pod 名。target.name 是要绑定的节点。 测试依次检查：不存在的节点返回 404；有效绑定返回 200；旧版本重发返回 409；携带当前版本 重复绑定同一节点返回 200 且版本不变；改绑另一节点返回 409。

实现思路

确认 Node 和 Pod 存在，再检查版本与已有 nodeName。未绑定时通过 CAS 写入 nodeName； 已经指向同一目标时返回当前对象，指向其他目标时返回冲突。

测试方式

API-BINDING：不存在的节点被拒绝，旧版本冲突，换节点被拒绝。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
