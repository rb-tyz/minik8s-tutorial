Stage 1.2：设置根目录与 PID 空间

你的任务

为后台任务设置独立根目录和 PID namespace，让入口进程在容器里成为 PID 1。

程序怎样被调用

测试器会把你编译的程序作为一个长期运行的子进程启动。例如：

./bin/my-minik8s /tmp/course-run/work/driver

./bin/my-minik8s 是你的程序；后面的路径是测试器分配给这一轮的工作目录，在 Go 中通过 os.Args[1] 读取。测试器把一行 JSON 写进你的标准输入（stdin），你的程序处理后向标准输出 （stdout）写一行 JSON。调试日志写到标准错误（stderr）。接入选项 --driver 指向的就是这个程序。

本小节的正式提交在获批的实验 KVM 内执行。测试程序与目录的准备见 从空 main 到第一次提交。

从节点 PID 到容器 PID

PID 是 Linux 给进程分配的编号。PID namespace 为一组进程提供单独的编号视图。你的程序需要 把任务放进新的 PID 与挂载视图，并把传入 rootfs 作为任务看到的根目录。

测试器发送 container-run，这次参数改为 args:["pause"]、wait:false。pause 会持续运行， 便于检查；wait:false 要求创建完成后立即回答：

{"ok":true,"id":"task-1","pid":2451}

id 是你为任务保存的身份。pid 是实验 VM 从外部观察到的进程编号，后面的 2451 只是例子。 测试器会读取 /proc/2451/status，要求该进程在自己的 PID 视图中编号为 1，并检查 /proc/2451/root/fixture 确实指向提供的测试程序。

请求还带 nonce，例如 run-a。把它传给任务的环境变量 GRADER_NONCE=run-a，测试器用这个 标记确认你返回的 PID 属于本轮任务。收到 reset 后，结束这个任务并释放它的资源。

实现思路

先保存创建出的任务身份与节点侧 PID。按原教程第六节建立 PID/mount namespace 和根目录， 再执行测试程序。使用 runc 时，这些配置放进它的运行配置；自行调用 Linux 接口时，需要 安排子进程完成隔离和根目录切换后再执行入口。返回 PID 前确认入口已经开始运行。

测试方式

CONTAINER-PIDROOT：节点侧 PID 有效；容器中 PID 为 1；根目录里能找到 /fixture。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
