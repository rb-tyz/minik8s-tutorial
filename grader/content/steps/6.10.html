Stage 6.10：重启后接管现有容器

你的任务

让 kubelet 重启后读取并接管已有任务。

程序怎样被调用

本阶段实现 kubelet，也就是在一个节点上负责运行 Pod 的组件。Pod 是对“运行哪些容器”的描述： spec 保存期望配置，status 保存观察结果。kubelet 读取分配给本节点的 Pod，调用前两节的 运行时接口，再把结果写回 API。

测试器调用 ./test-hooks/start node /tmp/course-run/work/lifecycle，由你的脚本启动 API 和 kubelet。随后它创建已经填写 spec.nodeName 的 Pod，并等待结果。这里使用节点网络，Pod 网络 在第九小节实现。本节在实验 KVM 内运行，测试程序和镜像由实验环境准备。

重启后先观察已有任务

测试器启动一个 Pod，记住应用 containerID 与 Node 条件中的 lastHeartbeatTime，然后调用：

./test-hooks/restart kubelet /tmp/course-run/work/lifecycle

只重启 kubelet，继续使用本轮数据目录。测试随后要求 Node 产生新心跳，Pod 仍为 Running， containerID 与重启前相同。lastHeartbeatTime 是节点最近一次报告健康状态的时间。

实现思路

启动时从运行时读取已有 sandbox/容器，用保存的身份或运行时标签关联到 Pod。接管当前任务， 继续更新心跳和状态，再处理缺少的资源。
