Stage 7.1：筛选可用节点

你的任务

从未绑定 Pod 出发，选择 Ready 且有可用容量的节点。

程序怎样被调用

本小节实现 scheduler（调度器）：给尚未填写 spec.nodeName 的 Pod 选择节点，并通过 API 的 绑定操作写入选择结果。测试器调用 start scheduler 数据目录，由启动脚本运行 API 与调度器。

测试器通过 HTTP 提供 Node 与 Pod 对象，再观察 Pod 的绑定结果。本节可在普通用户环境运行； 节点状态由测试输入提供，容器的实际运行由后续集成测试验证。CPU 数字使用毫核，1000 表示一个核； 内存数字使用字节。

测试会提供三种 Node

测试器创建不健康节点、零 CPU 容量节点和健康节点。健康信息放在：

{"conditions":[{"type":"Ready","status":"True"}]}

这是 Node.status 的一部分，True 在本课程里是字符串。不健康节点的状态为 False，健康节点 还提供 allocatable.cpu=2000 与可用内存。测试再创建请求 500 毫核、nodeName 为空的 Pod。

它等待该 Pod 的 nodeName 指向唯一的健康节点。

实现思路

List 节点和待调度 Pod，按 Ready 与资源条件过滤候选节点。选择后读取 Pod 当前版本，调用 第四小节实现的 binding 接口提交选择。暂时没有候选节点时保持未绑定，稍后重新尝试。

测试方式

SCHED-FILTER：不健康与零容量节点被排除，Pod 绑定到健康节点。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
