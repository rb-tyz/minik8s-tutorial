Stage 10.2：区分多个 TCP 端口

你的任务

让一个 Service 的两个 TCP 端口分别到达指定应用端口。

程序怎样被调用

本小节实现 Service Proxy。Service 给一组 Pod 提供固定的虚拟 IP（ClusterIP）；Endpoints 列出当前可用的 Pod 地址和端口。Proxy 读取这两种对象，在节点上维护转发规则。

测试器调用 start all 数据目录，由脚本启动 API、kubelet、scheduler、控制器和 Proxy。 随后它创建对象、等待真实容器就绪，再向 Pod IP 或 Service IP 发送请求。本节在实验 KVM 内运行。 本文地址用于展示数据关系，程序按实际对象中的地址和端口生成规则。

同一个 IP 的不同端口

测试器在一个 Pod 中启动两个 HTTP 程序：8080 返回 first，8081 返回 second。Service 配置 18080→first、18081→second，两个目标都是端口名。

Service-IP:18080 → Pod-IP:8080 → first
Service-IP:18081 → Pod-IP:8081 → second

测试分别请求两个入口，要求正文对应。一个 Service 可以提供多个端口，每条端口声明都要 独立参与匹配和目标解析。

实现思路

把 Service 身份、协议、入口端口组合为转发规则的身份，再分别查找目标端口。 沿用上一阶段的地址分配和更新逻辑。

测试方式

PROXY-MULTIPORT：两个入口分别得到 first 与 second。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
