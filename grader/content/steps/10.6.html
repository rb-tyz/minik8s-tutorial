Stage 10.6：重启时保留无关规则

你的任务

重启 Proxy 后恢复自有规则，并保留其他程序的 NAT 链。

程序怎样被调用

本小节实现 Service Proxy。Service 给一组 Pod 提供固定的虚拟 IP（ClusterIP）；Endpoints 列出当前可用的 Pod 地址和端口。Proxy 读取这两种对象，在节点上维护转发规则。

测试器调用 start all 数据目录，由脚本启动 API、kubelet、scheduler、控制器和 Proxy。 随后它创建对象、等待真实容器就绪，再向 Pod IP 或 Service IP 发送请求。本节在实验 KVM 内运行。 本文地址用于展示数据关系，程序按实际对象中的地址和端口生成规则。

重启时识别规则归属

测试器先向 NAT 表加入一条本轮独立链，链中只有 RETURN 规则，再调用：

./test-hooks/restart proxy /tmp/course-run/work/lifecycle

恢复后，它运行 Deployment→Pod→Service 的实际访问，确认转发正常，再检查刚才那条独立 链的 RETURN 规则仍然存在。那条链属于测试准备，不属于你的 Proxy。

实现思路

启动时从 Service 集合恢复已分配地址，重新观察 Endpoints，重建自己管理的转发链。 给自有链安排可识别的名称和更新范围，保留其他程序的规则。
