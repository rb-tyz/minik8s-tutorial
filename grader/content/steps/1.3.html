Stage 1.3：隔离网络与主机名视图

你的任务

为任务建立独立的 network、UTS 和 IPC namespace。

程序怎样被调用

测试器会把你编译的程序作为一个长期运行的子进程启动。例如：

./bin/my-minik8s /tmp/course-run/work/driver

./bin/my-minik8s 是你的程序；后面的路径是测试器分配给这一轮的工作目录，在 Go 中通过 os.Args[1] 读取。测试器把一行 JSON 写进你的标准输入（stdin），你的程序处理后向标准输出 （stdout）写一行 JSON。调试日志写到标准错误（stderr）。接入选项 --driver 指向的就是这个程序。

本小节的正式提交在获批的实验 KVM 内执行。测试程序与目录的准备见 从空 main 到第一次提交。

每个 namespace 管哪一部分

继续使用上一阶段的后台任务请求：args:["pause"]、wait:false，并返回节点侧 pid。 network namespace 提供独立网络接口和路由；UTS namespace 隔离主机名；IPC namespace 隔离一组进程间通信资源。

假设返回 pid=2451，测试器分别比较：

/proc/2451/ns/net  与 /proc/self/ns/net
/proc/2451/ns/uts  与 /proc/self/ns/uts
/proc/2451/ns/ipc  与 /proc/self/ns/ipc

每对链接应代表不同的 namespace。这里先检查隔离边界，容器之间的网络连通在第九小节实现。 任务仍需要携带请求中的 GRADER_NONCE，并在 reset 时结束。

实现思路

在创建任务的配置中逐项加入 network、UTS、IPC 隔离。每加入一项，都可以在 VM 内读取 对应的 /proc/<pid>/ns/ 链接确认。沿用上一阶段的根目录、PID 返回和任务记录。
