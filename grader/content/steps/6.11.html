Stage 6.11：度过 API 短暂中断

你的任务

处理控制平面暂时不可用的情况。

程序怎样被调用

本阶段实现 kubelet，也就是在一个节点上负责运行 Pod 的组件。Pod 是对“运行哪些容器”的描述： spec 保存期望配置，status 保存观察结果。kubelet 读取分配给本节点的 Pod，调用前两节的 运行时接口，再把结果写回 API。

测试器调用 ./test-hooks/start node /tmp/course-run/work/lifecycle，由你的脚本启动 API 和 kubelet。随后它创建已经填写 spec.nodeName 的 Pod，并等待结果。这里使用节点网络，Pod 网络 在第九小节实现。本节在实验 KVM 内运行，测试程序和镜像由实验环境准备。

API 暂时不可读时保留什么

测试器先让一个 Pod 运行，再调用 stop apiserver 结束 API，等待三秒，然后独立查询运行时。 该应用必须仍处于 CONTAINER_RUNNING。随后 start apiserver 恢复服务，测试继续等待原 Pod 报告 Running。

这次中断发生在读取期望状态的通信链路。已有任务的存在并不会因一次读取错误而改变。

实现思路

分别处理“成功读到空集合”与“本轮读取失败”。失败时保留已有任务记录，等待恢复后重新 观察。启动脚本恢复 API 时复用原存储数据，kubelet 再接续上报。
