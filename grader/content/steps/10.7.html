Stage 10.7：验收完整的 MiniK8s

你的任务

把对象存储、调度、kubelet、控制器和网络连在一起。

程序怎样被调用

本小节实现 Service Proxy。Service 给一组 Pod 提供固定的虚拟 IP（ClusterIP）；Endpoints 列出当前可用的 Pod 地址和端口。Proxy 读取这两种对象，在节点上维护转发规则。

测试器调用 start all 数据目录，由脚本启动 API、kubelet、scheduler、控制器和 Proxy。 随后它创建对象、等待真实容器就绪，再向 Pod IP 或 Service IP 发送请求。本节在实验 KVM 内运行。 本文地址用于展示数据关系，程序按实际对象中的地址和端口生成规则。

把前面的能力组合起来

本项用真实 API 驱动完整流程：对象 CRUD 和 PATCH、List/Watch、创建 Pod 并调度运行、 ReplicaSet 删除补副本、Deployment 更新模板，最后经 Service 访问实际应用。

测试程序会让不同版本的 HTTP 应用返回不同标记，用 API 观察与网络响应一起判断结果。 这次需要全套组件、运行时、镜像和 Pod 网络共同工作。

实现思路

按请求经过的顺序排查：对象是否保存、Pod 是否绑定、kubelet 是否创建真实容器、Pod IP 是否 可达、Endpoints 是否包含正确后端、VIP 规则是否生效。保持每个组件的状态更新与重试路径。 若父检查报失败，结果目录中的 legacy-all.log 会记录具体综合检查的位置；修复后重新提交。
