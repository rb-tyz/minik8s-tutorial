Stage 8.8：清理 Service 的自动后端

你的任务

在 Service 删除后清理自动生成的 Endpoints。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

Service 和自动后端的生命周期

测试器先验证命名端口生成与 Ready=False 撤下，再删除 Service：

DELETE /api/v1/namespaces/demo/services/endpoint
GET /api/v1/namespaces/demo/endpoints/endpoint

它轮询后面的 GET，直到得到 404。该 Endpoints 由你的控制器自动维护，随对应 Service 一起回收。

实现思路

记录或根据名称找到 Service 对应的自动 Endpoints。Service 删除事件到来后安排清理； 重试时允许目标已经不存在。保留与这个父对象无关的资源。

本小节的原理与接口说明

测试方式

CTRL-ENDPOINTS：删除 Service 后读取对应 Endpoints 得到 404。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

提交代码

minik8s submit

临时练习本阶段，保留课程进度：

minik8s submit --stage 8.8
