Stage 8.6：生成 Service 后端端口

你的任务

为 Service 匹配 Pod，并解析命名 targetPort。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

从 Service 找到实际监听端口

Service 的 selector 指定要访问的一组 Pod；targetPort 指应用监听的端口，也可以填写端口名。 测试器给 Pod 的容器声明 name=web、containerPort=8087，并把 Pod 报告为 Ready。

随后创建 Service，相关字段为：

{"selector":{"app":"endpoint"},"ports":[{"name":"http","port":80,"targetPort":"web"}]}

Endpoints 是控制器生成的后端集合。测试器查询 /api/v1/namespaces/demo/endpoints/endpoint， 要求 subsets 中的地址包含 10.77.0.9，端口包含 8087。

实现思路

按 selector 匹配就绪 Pod，从容器端口声明解析 web，再生成地址与端口记录。Service 的访问 端口 80 和后端监听端口 8087 分别保存，供 Proxy 做转发。

测试方式

CTRL-PORT：名为 web 的目标端口解析为 8087。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
