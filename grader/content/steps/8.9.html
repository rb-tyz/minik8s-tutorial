Stage 8.9：在重启后继续调谐

你的任务

让控制器恢复已有对象，并处理后续扩容。

程序怎样被调用

本小节实现控制器：持续比较“用户想要的对象”与“API 中已有的对象”，补做创建、更新或删除。 测试器调用 start controllers 数据目录，由脚本启动 API 和控制器程序。

测试器主要通过 HTTP 创建父对象，再查询子对象。这里可在普通用户环境运行，Pod 的就绪状态 由测试器通过 /status 写入，便于先检查控制算法。实际容器和通信在第十小节组合验收。

重启后的第一轮从哪里开始

测试器创建一个副本的 ReplicaSet，记住它的子 Pod UID，调用：

./test-hooks/restart controller-manager /tmp/course-run/work/lifecycle

控制器恢复后，测试器把期望副本数改为 2。结果应出现两个自有 Pod，其中原先的 UID 继续存在。

实现思路

启动时重新 List 建立观察，再接续 Watch；根据父对象重新把需要调谐的名称放入队列。 先识别已经存在的子对象，再补齐差额。存储中的父子身份比进程内缓存活得更久。

本小节的原理与接口说明

测试方式

CTRL-RESTART：重启后原 Pod UID 保留，扩容到两个副本。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。

提交代码

minik8s submit
