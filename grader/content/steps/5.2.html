Stage 5.2：标记初始同步结束

你的任务

在初始对象之后发送 BOOKMARK。

程序怎样被调用

本阶段继续运行 API 服务。测试器用 HTTP 建立 Watch 长连接，再从另一个连接创建或删除对象。 Watch 表示持续订阅对象变化；返回格式是 NDJSON，即每行一个 JSON 事件。

本页 URL 使用 demo 作为 namespace 示例。一个事件中的 type 表示变化类型，object 是对应 对象。resourceVersion 是对象或快照的存储版本，用于说明从哪里接收后续变化。 API 的启动和停止仍使用 --adapter 指定的脚本目录。

怎样知道初始对象已经发完

继续处理缺省版本的 Watch。本阶段要求先发送已有 Pod 的 ADDED，再发送 BOOKMARK，例如：

{"type":"BOOKMARK","object":{"metadata":{"resourceVersion":"10"}}}

BOOKMARK 是一个进度标记，表示版本 10 的初始快照已经完成。它不表示新增了一个 Pod。 测试器要求其版本为正数，并确认它位于 ADDED 之后。

实现思路

在一次受保护的读取中取对象集合和快照版本。先发送集合，再发同一快照位置的 BOOKMARK， 然后接续这个位置之后的变化，防止初始化和实时流之间出现空隙。

测试方式

WATCH-BOOKMARK：ADDED 位于 BOOKMARK 之前，bookmark 携带快照位置。

本阶段使用 普通用户 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
