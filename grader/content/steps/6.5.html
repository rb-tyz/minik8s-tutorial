Stage 6.5：向容器传入环境变量

你的任务

将 spec 中的 env 传入应用容器。

程序怎样被调用

本阶段实现 kubelet，也就是在一个节点上负责运行 Pod 的组件。Pod 是对“运行哪些容器”的描述： spec 保存期望配置，status 保存观察结果。kubelet 读取分配给本节点的 Pod，调用前两节的 运行时接口，再把结果写回 API。

测试器调用 ./test-hooks/start node /tmp/course-run/work/lifecycle，由你的脚本启动 API 和 kubelet。随后它创建已经填写 spec.nodeName 的 Pod，并等待结果。这里使用节点网络，Pod 网络 在第九小节实现。本节在实验 KVM 内运行，测试程序和镜像由实验环境准备。

env 要进入实际进程环境

测试器创建一个 Never 策略的 Pod，设置：

{"env":[{"name":"CHECK","value":"correct"}],"args":["env","CHECK","correct"]}

这两个字段位于应用容器配置中。env 是要注入的环境变量列表；参数要求 fixture 在进程里 读取 CHECK，等于 correct 时退出 0，否则退出 3。

测试等待 Pod 为 Succeeded、退出码为 0。

实现思路

在创建应用容器时，把 name/value 列表转成运行时接受的环境配置。把命令、参数与环境一起 传给实际任务，随后按运行时终态更新 Pod。

测试方式

NODE-ENV：容器内读到 CHECK=correct，检查任务成功退出。

本阶段使用 KVM 环境，只执行这一项检查。测试会准备本次输入，并在结束后回收本次资源。
