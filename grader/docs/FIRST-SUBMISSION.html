从空 main 到第一次提交

第一关只要求启动一个普通子进程，等待它结束，返回退出码 0。每次 minik8s submit 都会自动创建一次性 KVM，并在 guest 内执行本关；正常流程不需要手工创建 VM 或填写 UUID。测试器在 guest 中以 root 启动被测程序，1.1 可使用普通子进程或容器运行时。

实现会一直保留

第一关把参数解析、启动与等待、JSON 输出分成几个普通函数即可。可以用 os/exec 启动普通进程，也可以直接使用完整容器运行时；1.1 不要求同时维护普通和容器两条必需分支。后续关卡增加参数、后台分支和 reset，继续复用这些函数。进入 CRI、KV、API 后增加相应操作入口；重构可以整理内部结构，原有接口和检查继续有效。

你会用到三个程序。minik8s submit 是课程测试器；./bin/my-minik8s 是你编写的程序；lab/rootfs/fixture 是课程提供的测试程序。第一关的调用顺序是测试器启动 my-minik8s，my-minik8s 再启动 fixture。

准备测试程序

在自己的工程目录安装课程命令，并编译课程提供的 fixture。下面假定 Go module 位于 src；已有其他目录结构时调整路径。

bash grader/install.sh
mkdir -p bin lab/rootfs/tmp
CGO_ENABLED=0 go build -o lab/rootfs/fixture grader/fixtures/process.go
minik8s init --driver ./bin/my-minik8s --fixture ./lab

课程命令默认从 ~/.cache/minik8s/vm/base.qcow2 启动一键 VM，并用同目录 base.sha512 校验。这两个文件由课程环境准备；缺少或校验失败时，提交会在运行测试前停止。

fixture 是课程提供的测试程序，首次使用时编译一次。每次运行 minik8s submit，测试器都会在 src 中执行 go build -buildvcs=false，把你的程序编译到 bin/my-minik8s。编译出错时，终端会显示 Go 的报错，本次提交在测试开始前结束。

第一关的调用

./bin/my-minik8s container-run --state-dir work --rootfs lab/rootfs \
  --cgroup-parent "$parent" --nonce run-a --wait true --arg=exit --arg=0

解析 container-run 后的参数，用 os/exec 启动 rootfs 下的 fixture，传入 exit、0，等待结束。--state-dir、--nonce 和 --cgroup-parent 在本关接收即可；$parent 是测试器在 guest 内预建的绝对 cgroup v2 父路径。stdout 返回一个 JSON 对象，命令自身退出 0：

{"ok":true,"exitCode":0}

本关不调用 reset。--cpu、--memory、--pids 在后续 stage 才出现；--cgroup-parent 从 1.1 起每次都随 container-run 调用传入。测试日志写 stderr；后续阶段会分别检查参数原样传递、非零退出码和输出隔离。

提交与继续

minik8s stage
minik8s submit
minik8s report
minik8s serve

通过后进入 1.2。修改源码后再次运行 minik8s submit 即可。指定 minik8s submit --stage 1.1 是练习，不改变当前进度。

1.1–1.5 处理普通等待执行，1.6 加入后台任务，1.7 再实现 reset。所有 stage 都在 submit 自动创建的一次性 KVM 内执行；1.8 起在同一个 guest 内加入根目录、namespace 和资源限制。reset 只回收自己记录的任务与 child cgroup，父 cgroup 由测试器清理。
