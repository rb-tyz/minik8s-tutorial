按小节与 stage 提交

课程保留原教程的十个小节，在小节内拆分为 170 个 stage。每次普通 submit 只验收当前 stage 的一项能力，通过后进入下一项。初次接入先读 从空 main 到第一次提交。阶段目录见 课程目录。

安装与配置

在仓库根目录或交付包解压目录执行：

bash grader/install.sh
cd /path/to/my-minik8s
minik8s init --driver ./bin/my-minik8s --fixture ./lab
minik8s stage
minik8s submit

上例从 1.1 开始，./lab 包含课程测试文件。按默认 Go 布局提交时，课程命令先在本机工程运行 go build -buildvcs=false，再创建一次性 KVM，将生成的 bin/my-minik8s 和配置的测试文件复制到 guest 中执行测试。正常提交流程自动分配 VM 和 UUID。测试器优先从 src/ 构建，也支持 Go 主包位于工程根目录的布局。省略 --driver 时，Go 工程使用相同的默认输出路径。显式指定其他可执行文件时，测试器使用该文件，构建由提供它的项目负责。

终端和网页都使用这一步骤。--through 和 --all 每次提交编译一次，所有关卡测试同一份产物。编译失败时会保存编译器输出并结束本次提交，课程进度停留在原关。第四小节再添加 --adapter ./test-hooks，指定启停脚本目录。

安装脚本在 ~/.local/bin/minik8s 创建链接，保留仓库或解压目录即可使用；该目录应在 PATH 中。 命令需要 Python 3。配置支持 adapter、driver、url、cni、fixture、vm-id、driver-protocol，协议见 接入说明。相对路径按学习者项目目录解析。vm-id 只在底层入口已经由外部提供 guest 时使用；普通 submit 不需要填写。

阶段编号

3.1 表示第 3 小节的第 1 个 stage。例如 KV 小节依次验收：

3.1 写入并读取一个键
3.2 读取不存在的键
3.3 覆盖已有键
3.4–3.6 前缀 List、空结果与排序
3.7–3.9 提交版本、创建版本与列表快照
3.10–3.14 CAS 与删除
3.15–3.19 Watch 重放、实时事件、删除、取消、超时
3.20–3.22 压缩边界、过旧游标与崩溃恢复

minik8s stage 3.1      # 阅读该 stage 的任务
minik8s section 3      # 阅读整个 KV 小节的原理与接口说明
minik8s stages         # 查看分组目录与进度
minik8s status         # 查看当前学习进度
minik8s submit         # 验收当前 stage
minik8s report         # 阅读最近一次提交报告

单个数字 3 是 3.1 的便捷别名。选择 stage 和临时提交时都可以使用。

普通提交要求检查本身通过、测试进程成功退出，并确认清理。失败时保留当前 stage； 中断时等待测试器清理。重启终端或服务后，在同一项目目录继续提交即可。

练习与全量验收

minik8s submit --stage 3.4
MINIK8S_COURSE_STAGE=3.4 minik8s submit
minik8s submit --all

临时选择只记录本次结果，保留学习进度。命令参数优先于环境变量；全量验收前应取消临时 stage 环境变量。--all 从头逐项执行 170 项，遇到首个失败停止，并保存连续通过的前缀。 已通过的进度保留。课程完成后，普通 submit 提示完成，--all 仍可重测。

原有综合回归入口继续可用：

bash grader/test.sh --stage 3 --driver /path/to/driver --output /tmp/kv-section-new

这里的 --stage 3 沿用底层脚本编号，表示整个原教程 KV 小节。底层单项入口为：

bash grader/test.sh --stage 3 --step KV-PUT-GET \
  --driver /path/to/driver --output /tmp/kv-get-new

底层 --only 继续服务于原 44 项综合检查。细分 --step 与它分开，避免改变原检查语义。

进度迁移与存储

项目内 .minik8s/ 保存配置、进度和运行记录。配置仍为 schema 1；课程进度使用 schema 3， 提交报告和事件带 course_version=3。passed_stages 是按顺序排列的 "3.1" 等编号，current_stage 为下一关或 null。

v1/v2 进度按旧检查的实际覆盖范围映射。新增能力需要重新验收，已覆盖能力及原始通过记录保存在 migration 字段中。 读取只计算新视图；首次保存时备份为 progress.v1.json 或 progress.v2.json，已有备份不覆盖。 例如旧版完成第一小节可证明新版 1.1；参数原样传递是新增检查，继续位置是 1.2。 旧运行日志和报告保留原版本，课程升级不会重写历史结果。

每个项目只允许一个提交或配置写入操作。进度通过临时文件同步后原子替换，配置更新与进度 迁移共用项目锁。建议在学习者项目的 .gitignore 中加入 .minik8s/。

.minik8s/
  config.json
  progress.json
  progress.v1.json          从旧版迁移时生成
  lock
  runs/<run-id>/
    runner.log
    events.jsonl
    result.json
    report.md
    test/3.1/              每个 stage 独立的请求、响应与清理结果

从其他位置使用 minik8s --project /path/to/project submit 选择项目。

页面与机器接口

minik8s serve 打开本地课程界面，见 本地界面说明。 JSON 查询和事件入口为：

minik8s stages --json
minik8s section 3 --json
minik8s stage 3.1 --json
minik8s status --json
minik8s report --json
minik8s submit --events

stages 返回 sections 分组与 stages 任务；每个 stage 包含字符串 ID、小节、位置、任务正文、 提示、检查项与命令。前端使用 instructions_markdown 渲染任务，instructions_path 标记包内位置。 status 返回连续通过的 passed_stages、current_stage、latest_run。

事件 envelope 的 schema_version 为 1，课程结构标记 course_version=3。submit --events 的 stdout 为 NDJSON，stderr 为命令级错误。事件包含 sequence、type、run_id、time； 类型包括 run.started、build.started/passed/failed、stage.started、check.started/passed/failed、stage.tests_finished、 stage.passed/failed、run.interrupted、run.finished。阶段通过在退出与清理确认后发出。

测试失败时

终端会显示失败检查、被测程序的错误和本轮结果目录。先读这段输出，修改后重新运行 minik8s submit。编译错误发生在本机工程；镜像校验错误发生在启动 guest 之前。

要复查上一轮，运行 minik8s report。在结果目录的 test/关卡号/ 下，summary.json 给出断言和清理结果。命令行关卡的 driver-commands.jsonl 保存传给你的参数，driver.log 保存 stderr；服务关卡可查看 hooks.log 和 requests.log，CNI 插件报错在 cni.log。每轮使用独立的工作目录。

实验和复验

普通提交在一次性 KVM 中运行选定关卡，KVM 内的进程负责读取本轮的 /proc、cgroup 和网络状态。 早期 API stage 使用本次独立 API 进程，依靠 adapter 的 stop 清理，因此需要生命周期 适配器；它们的启动探测与验收不要求 Node List 或尚未教学的其他 HTTP 操作。

普通 minik8s submit 从 ~/.cache/minik8s/vm/base.qcow2 启动 guest，并用同目录的 base.sha512 校验； 缺少镜像或校验不匹配时，测试在开始前停止。下面是维护者用显式 VM 镜像复验的命令：

python3 -m unittest discover -s grader/tests -v
python3 grader/verify-course.py --output /tmp/fine-course-check-new
python3 reference/tests/vm/run.py --course-cli \
  --image "$LAB/base.qcow2" --sha512 "$IMAGE_SHA512" \
  --crictl "$LAB/crictl.tar.gz" --crictl-sha256 "$CRI_SHA256" \
  --output /tmp/fine-course-vm-new

VM 流程依次验证连续提交、170 项细分全量和原 44 项综合回归。 环境准备与校验见 VM 说明。

默认调用协议为 auto：第一、二小节用命令行参数，第三小节用本机 HTTP。已有 JSONL 实现可设置 minik8s init --driver-protocol jsonl；新实现按各 stage 页面接入。

回归已经实现的前缀

minik8s submit --through 1.7

从 1.1 顺序运行到指定关卡，遇到失败停止。报告的 mode 为 regression，保存逐关结果和失败位置；通过、失败均保留 passed_stages 与 current_stage，仅更新最近报告。完成全部课程后也可使用。

--through 与 --all、--stage、环境变量 MINIK8S_COURSE_STAGE 互斥。回归同样使用 submit 自动创建的一次性 KVM。单关练习仍用 --stage，正常提交仍只验收当前关卡。
