11 实验与教程覆盖检查

验收依据是参考实现的实验正确性，以及教程对实现机制和实验步骤的覆盖。学习者反馈作为 后续改进材料。本表用于逐章检查这两项依据。

最新实现的逐项实验 ID、测试入口和结果见验收报告中的 ORIG-* 矩阵。报告保存了 43 项 单节点断言和 13 项双节点断言的通过记录，以及后续 CLI 检查与测试统计。

每次变更怎么检查

先核对实现与已公布契约，再检查教程是否说明了该行为的原因和实现步骤。重点包括： 身份/版本与 CAS；List/Watch 的连接与退出；控制器重复协调；资源请求与运行时限制； 镜像缓存与拉取失败；网络地址复用、跨节点路由、VIP 分配者；删除后的实际资源回收。

实现中的私有日志编码、包结构和工具选择可以有不同方案。课程必需机制在正文解释， 参考实现细节放在契约或实现说明中。每个实验应给出输入、命令、预期断言及失败现场， 并指向实际记录。发现教程缺口时补足说明；行为变化时重跑相关实验后更新结果。

本阶段检查方法

course.json（本地工程附件） 按模块登记原文/订正、公共契约及十项教学要求所在的章节。 九个模块章共 90 个要求位置，00/10 与实验页补充环境及完整操作。映射由本轮逐章核对， 脚本检查章节与证据位置是否仍然有效：

python3 tutorial/check_course.py --output /tmp/opencode/course-review-new.json

脚本还检查本地链接、示例 JSON、全部 56 项原生运行断言的教材归属，以及第二阶段快照中 93 份实现/测试/脚本的 SHA-256。新增 Core 实验的实际执行和四份示例 API 响应保存在 第三阶段证据（本地工程附件）。

检查层次 本次依据
正文与实现对应 逐章读契约/源码并补充计算、状态、并发与恢复步骤
新增命令与对象 真实 API 的 CRUD/PATCH/Watch、四份示例 POST/GET/DELETE
节点/网络行为 第二阶段 43+13 项 KVM 断言；本次实现文件哈希一致
课程交付检查 章节要求索引、链接、JSON、Bash 语法与实验 ID

故障和异常用例是否已运行按对应报告列出。私有日志编码、工具参数与加固选择分别在契约 或环境页说明。第四阶段继续扩充可供其他实现使用的黑盒检查，当前入口见 grader/README。

课程维护者还可验证已发布的请求构造与实验入口：

python3 tutorial/labs/verify-material.py --api-binary "$COURSE_BIN/mini-apiserver" \
  --output /tmp/opencode/course-material-new

COURSE_BIN 按 Core 实验构建，运行此检查前保留该二进制。检查实际执行滚动 PATCH 与 退出/init/只读卷的 jq 请求构造，提交给独立 API；还验证已有 API 接入模式保留进程， 启动失败被拒绝且临时 WAL 清理。容器内行为对应第 06 章既有 KVM 记录。
