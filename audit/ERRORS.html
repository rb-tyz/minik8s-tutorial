API-001 · 编码响应时必须由 KV revision 回填对象 RV

  • 分类：实现缺口
  • 严重程度：Critical
  • 原文位置：§9.2 行 975–1002（meta.ResourceVersion = "" → s.kv.Put(key, bytes, 0) → 之后才 meta.ResourceVersion = fmt.Sprintf("%d", rev) 并重编码返回给客户端）
  • 触发条件：100% 必现。任何 create 之后的 GET/LIST/watch。
  • 原因与证据边界：写入 JSON 中 RV 为空或落后，KV.Get/Range 同时返回正确 revision；GET/LIST 的编码层未给出。
  • 复现证据：evidence/go/apiserver/apiserver_test.go::TestPersistedObjectLacksResourceVersion → minikv holds rev=1 but the stored JSON has metadata.resourceVersion="" (response said "1")
  • 修复或实施建议：GET/LIST/WATCH 统一用存储 revision 回填 RV；无需额外 Put。
  • 影响范围：辅助编码器若原样返回存储字节，客户端缺少可用 RV；原文缺失的 GET/LIST 编码器可以正确补齐。
  • 验证状态：辅助实现观察
  • 官方依据：见 evidence/research/SOURCES.txt 中对应模块规范
  • 关联记录：相同 ID 见 AUDIT.md 的模块分析和证据索引

API-002 · update 不校验 name/uid，不保护 identity 字段

  • 分类：实现缺口
  • 严重程度：High
  • 原文位置：§9.2 行 1009–1030（handleUpdate 直接用 body 覆盖 URL key）
  • 触发条件：PUT 的 body 与 URL 的 name 不一致，或伪造 uid。

  • 影响范围：缺少 identity 校验的适配器会接受错误字段；完整 API 需用 body/URL 不一致测试验证。

API-004 · watch 不 flush header，客户端无法确认订阅

  • 分类：原文错误
  • 严重程度：High
  • 原文位置：§10.2 行 1084–1095（WriteHeader(200) 后直到首个事件/30s bookmark 才 Flush）
  • 触发条件：安静的前缀（无事件）。
  • 原因与证据边界：WriteHeader 只写缓冲；需显式 Flush 才能发送 header。

  • 影响范围：客户端 30s 内不知道 watch 是否被接受；超时设置短则误判断线。
  • 验证状态：用户态复现

  • 分类：原文错误

  • 修复或实施建议：逐层委派（root→slice→pod→container），逐层检查 cgroup.controllers； 不要写不存在的控制器。
  • 影响范围：§6.2 的“最小可用容器”完全不能启动。
  • 验证状态：隔离 KVM 复现
  • 官方依据：cgroup v2 文档 "Enabling and Disabling Controllers"。
